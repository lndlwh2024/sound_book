# 发布平台与标题配置（2026.10.19.6）

完整版与独立部署版使用同一份昵称识别、部署前检查、标题生成和平台显示配置。

## 微信视频号登录与昵称

此前浏览器已登录、用户已确认登录时，实际昵称字段仍可能为空，部署在静态配置检查阶段被拦截，尚未上传文件。本次补充左下角本人账号区的识别，兼容旧侧栏、新账号菜单卡、`display: contents` 及 CSS 生成文字；不会把作品作者、预览作者、隐藏账号或多个互相冲突的名字当成本人账号。

“登录 / 刷新账号”和“读取昵称”继续沿用该账号原有浏览器目录，不需要删除账号或重复扫码。部署前缺少微信视频号昵称时允许进入只读实时检查，从当前已登录会话取得唯一的本人昵称；确认成功后在界面线程保存到原稳定账号ID，再启动上传。已绑定账号与页面账号不一致时仍停止部署，登录页、安全验证及无法确定的身份不会被放行。账号区域DOM采样同时补齐文字与CSS生成文字，便于后续诊断。

## 四种统一标题来源

所有发布适配器，包括当前隐藏的小红书，都共用 `src/publisher/titles.py`。

| 选项 | 行为 |
| --- | --- |
| 空 | 清空对应标题字段，不自动补入文件名；平台要求必填时提示配置问题，不绕过平台校验 |
| 系列名称 | 按现有规则从文件名提取系列名称 |
| 文件名 | 使用文件名称，去掉扩展名 |
| 自定义 | 显示同行输入框，使用该账号保存的自定义标题；未填写时在配置检查中提示 |

微信视频号写入“短标题”，视频描述继续留空，合集及“不显示位置”沿用原配置。其他平台继续填写各自已有的标题/作品描述字段并遵守长度限制。话题与标题是不同字段；抖音原来未生效的话题输入框隐藏，历史标签配置保留。

旧账号没有新标题配置时保持此前实际行为：抖音取系列名称；快手、小红书、YouTube沿用原标题规则；微信视频号沿用旧固定短标题或留空。界面保存后使用明确的四种来源及自定义内容，不改变账号ID、浏览器登录目录、成功账本或日期断点。

## 平台显示与执行顺序

当前界面的平台顺序统一为：**抖音 → 快手 → 微信视频号 → YouTube**。配置下拉、发布目标勾选、监视队列平台列、日志标签及实际任务调度保持一致。

小红书仅隐藏界面和自动任务入口。`CHANNELS` 注册、账号数据、登录目录、历史结果、适配器及测试保留，共用功能迭代仍覆盖小红书。恢复时调整 `HIDDEN_CHANNELS` 显示设置即可，无需重建账号或重新接入架构。历史日志仍可在全部日志、原报告及诊断导出中查看。

旧自动恢复名单含小红书时暂停该旧计划，并提示重新选择当前可见平台；不悄悄启动隐藏平台、不删除历史名单，也不把它替换成其他账号。当前任务的成功去重、失败重试、每日额度、云盘共享下载、补扫及 `publiced` 归档条件保持原有规则。

## 更新与验收

运行中的旧进程不会自动加载代码。先停止部署并安全退出，再重启完整版或完整替换部署程序；保留原用户数据。无需清空账号、重登所有平台或重新采集全部DOM。

本机使用临时账号、隔离目录和本地网页验证昵称识别/拒绝、部署前身份保存、所有适配器的四种标题来源、隐藏平台保留、执行顺序、1366×768布局及现有生产/发布回归。验证记录在 `artifacts/publishing-options-20261019`。没有对真实账号执行上传或发表，目标机实际发布仍需现场验收。

最终合并结果：完整版环境455项通过，部署固定依赖环境128项通过。YouTube原有完整投稿流程的6组本地网页测试通过，小红书/快手实际适配器串行完成后归档测试通过。原生产模块、云盘下载、额度及上版统一归档模块源码未改动；调度仅调整平台排序。配置窗不添加滚动条，自定义标题同行显示，两版均使用相同选项与存储实现。
