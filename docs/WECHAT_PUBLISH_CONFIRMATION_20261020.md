# 微信视频号发表后继续下一文件

统一版本：2026.10.20.10。完整版及独立部署版使用相同微信视频号适配器。

## 现场原因

诊断包5中，任务06df553311604718ae809e3f3811c0d4于15:54:01点击“发表”，随后一直记录“平台结果尚未确认”；截图已进入视频管理页，用户随后在平台确认该作品确实已经发布。该诊断包在任务尚未退出时导出，因此没有本条任务最终的失败截图和DOM。

旧适配器仅监听 `/cgi-bin/mmfinderassistant-bin/post/post_create`。当前内容页面使用 `/micro/content/cgi-bin/mmfinderassistant-bin/post/post_create`，旧过滤条件忽略了正式发表回执。页面成功时实际显示带成功图标的 `.common-toptip` 提示“已发表”，旧代码仅识别“发表成功”及其他提示容器，第二条确认途径也漏掉了。

通过只读获取平台公开前端资源核对：当前[内容页面入口](https://channels.weixin.qq.com/micro/content/)加载的[内容服务代码](https://res.wx.qq.com/t/wx_fed/finder/helper/content/finder-helper-content/res/static/js/async/499.c64d1604.js)定义内容服务前缀与正式发表路径；[发表页面代码](https://res.wx.qq.com/t/wx_fed/finder/helper/content/finder-helper-content/res/static/js/async/772.c60547ed.js)在正式发表结果通过检查后显示“已发表”，约1.5秒后返回列表。代码不调用或重放这些接口，只监听正常浏览器点击产生的请求与响应。

## 修复结果

兼容当前及原有两个精确的HTTPS正式发表地址，继续要求请求发起于本次点击之后，并按同一请求匹配响应。业务成功码、内层业务错误及作品ID冲突的检查保持。保存回执时保留实际地址并去除查询参数；草稿、预览、列表、相似路径、其他主机及只有HTTP 200的响应都不能确认成功。

识别平台带成功图标的当前顶部提示及精确文案“已发表”，保留原“发表成功”兼容。正文、标题、作品列表中的文字和错误提示不作为本次成功证据。原有点击前旧成功提示检查保持。

确认后立即沿用公共流程保存成功账本和成功计数，完成浏览器原有收尾关闭；关闭后另行空闲等待5秒，继续下一个待发文件。成功结果重启后仍跳过，不重复上传。未确认的已提交记录继续保留待核验保护。描述仍保持平台默认空白，其他平台和制作管线不变。

日志增加正式发表请求的无查询参数地址；正式响应无法解析时明确说明原因，不再静默忽略。

## 已经由旧版发表的这条作品

新版本不能补回旧进程已经错过的网络回执，也不会仅凭一个列表页面把未知文件全部改成成功。独立部署版先停止旧任务，进入“运行设置 → 核验中断投稿”，对已经在平台核实的对应文件选择“已在平台确认发布”，再继续部署其他文件。沿用原账号及登录数据，无需重登或重新采集DOM。

## 验证范围

本地真实浏览器验证新旧回执、无有效回执、业务拒绝、当前顶部提示、嵌套页面、空描述以及连续两个文件成功、浏览器关闭顺序和重启不重传；公共间隔测试确认浏览器收尾不计入5秒空闲等待。测试请求均被本地页面接收，不向真实平台投稿；实际Win10账号发布结果仍需现场复测。
