# 自定义昵称与部署前检查修复 · 2026.10.20.1

完整版与独立部署版共用同一实现与版本号。

## 现场原因

2026-10-20 的微信视频号失败证据显示：当前页面已经是 `/platform/post/create`，视频文件入口可用，短标题控件可见，但侧栏折叠为图标，账号区域只有头像，没有昵称文本。本次停在部署前读取昵称，尚未开始选择、上传视频。旧逻辑持续等待昵称直至超时，不能把这种现象判定为账号未登录。

## 使用方式

在账号矩阵池点击“自定义昵称”，或在登录与页面诊断窗口点击同名按钮，输入本地显示名并保存。若微信视频号部署前发现已打开的受保护上传入口可用、但页面只有头像，会在关闭检查浏览器后直接弹出昵称输入窗口；保存后重新启动部署即可。取消时不上传文件，可以稍后在账号矩阵池设置。

自动恢复遇到此类配置问题只显示等待原因，不反复打开账号首页，也不弹出循环提示。用户完成设置后手动启动部署。

`custom_nickname` 单独保存并显示“自定义”标记，不写成平台实际昵称，不把登录状态改为已授权，不替换账号 ID、浏览器目录、云盘目录及发布历史。后续读到真实昵称时仍保留本地显示名，真实昵称存入原字段。所有平台都可以设置本地显示名；YouTube 的真实频道 ID 校验继续执行。

## 实时检查与浏览器生命周期

- 配置缺失、已有登录/采集会话占用等已知错误在创建部署浏览器之前返回。
- 需要实时验证时使用原账号独立浏览器目录。自定义昵称不作为登录凭据；微信视频号必须位于正确域名的创建页面，有唯一可用的视频文件入口、可见短标题输入框及本人侧栏头像，且没有可见登录控件。支持 Wujie 开放 Shadow DOM。实际昵称能读取且与原绑定不匹配时仍阻止上传。
- 页面加载等待保留；不再在完整的仅头像页面上长时间等待并不存在的昵称。
- 检查失败时先采集失败截图、DOM 和完整任务日志，再关闭本次检查会话；必要时关闭同一会话所属浏览器，随后才返回界面提示。首个终止性检查失败后不继续打开其他平台。不会自动打开登录/采集页，也不关闭用户其他浏览器。
- 自定义名称模式下仍只接受本次真实发布回执。微信视频号成功回执与稳定账号 ID 绑定，保留重启后不重复上传、未知提交需核验的规则。

发布后的确认、重试次数、额度、共享下载及 `publiced` 归档规则沿用现有实现。生产流水线不变。

## 验证范围

使用本地受控页面复现仅头像、开放 Shadow DOM、隐藏但可用的视频文件输入、登录控件和错误账号；覆盖自定义昵称保存与重载、会话关闭顺序、完整上传流程、成功及未知提交重启去重。所有媒体与配置均位于测试临时目录，没有向真实平台投稿。发布包另行核对编译代码、清洁环境自检和 1366×768 布局；目标 X230 及真实账号发布仍需现场验收。
