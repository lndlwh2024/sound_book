# 发布页面停留计时（2026.10.25.3）

本版只增加页面和阶段耗时记录，完整版与独立发布版使用相同代码。登录判断、浏览器会话保留、上传顺序、YouTube等待条件和后续发布步骤均沿用原行为。

所有平台的部署前检查、自动上传和自动化登录/诊断窗口均记录：

- 页面停留：标签页ID、页面ID、脱敏网址、开始和结束时间、停留秒数、结束原因。主页面导航、页面关闭和浏览器结束时结算；iframe不会冒充新页面。
- 页面阶段耗时：同一个网址内执行的业务阶段，例如填写详细信息、等待上传处理及检查、配置公开范围。阶段结束、失败或中断时结算；页面跳转时也保留阶段与各页面的对应关系。
- ID是书声生成的诊断编号，不是平台的视频ID或账号ID；多次打开相同网址仍可区分。计时用单调时钟计算，系统时间调整不会改变耗时。

部署记录显示在右侧“发布全流程日志”的对应平台标签及“全部”标签，写入数据目录 `multi_platform/logs/publisher-events.jsonl`，并随当次任务日志进入最新任务诊断包。自动化登录/采集窗口还显示在该窗口的日志中；其记录独立落盘，不冒用发布任务编号。旧抖音兼容入口沿用其现有日志文件。

网址去掉查询参数、片段和用户信息，不读取Cookie或页面内容。正常手工登录Google的浏览器未连接自动化，无法记录其逐页面停留；不会为计时而改动这种登录方式。浏览器启动尚未返回时没有可观测页面，不能将启动失败伪造成某个页面停留。

YouTube截图里的“继续”表明后续向导尚未完成，但仅凭截图不能判定按钮识别失败。目前源码在进入后续向导前等待上传、处理及检查条件。该阶段耗时与页面停留记录用于定位等待位置；本版不提前关闭窗口或跳过步骤。

此前提出的4—8小时空闲验收尚未实现，也不会由本版自动执行。未来如实现，先采用独立的只读检查：空闲后打开既有账号的上传入口，检查登录页/上传入口并采集差异；不选择视频、不创建草稿、不保存或发布。它只能证明登录入口能否恢复，不能代替真实上传验收。真实上传验收需使用明确指定的正常待发视频，按正常部署立即连续处理，不能自动生成测试内容或故意延后下一份生产文件。
