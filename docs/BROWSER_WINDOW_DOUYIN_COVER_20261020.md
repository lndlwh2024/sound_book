# 浏览器窗口与抖音封面修复

统一版本：2026.10.20.7。完整版与部署版共用浏览器窗口策略、抖音修复及诊断信息。

## 本次现场证据

用户诊断包2中的最新启动版本为2026.10.20.6，2026-10-20 11:58:40。此前20.6只调整上传间隔及书声界面，没有修改浏览器窗口。

最新任务a475acfa在12:00:09和12:00:52分别失败一次，均停在“选择当前视频画面作为封面”。第二次日志明确包含“click action done”和“waiting for scheduled navigations to finish”；两次最后截图均已经出现封面编辑器。说明程序把已经完成的封面入口点击，因额外等待网页跳转超时而判为失败，尚未进入发布按钮检查和提交阶段。

失败DOM和完整页面截图中存在唯一底部“发布”按钮，启用且未禁用。用户截取的当前窗口只显示网页中段；旧代码同时使用1440×900窗口参数和固定网页视口，超过1366×768屏幕扣除任务栏、浏览器工具栏和提示栏后的真实可见范围。

## 窗口与滚动

有界面的浏览器统一使用最大化窗口，关闭固定网页视口模拟，让网页跟随窗口真实内部空间变化。移除旧窗口尺寸参数；浏览器工具栏及测试提示栏占用的高度自然从网页可用空间扣除。账号目录、私有浏览器选择和Google手工登录的专用目录不变。YouTube使用正常Chrome/Edge的自动化接管入口也沿用同一窗口策略。

长网页仍可滚动，不把整张发布表单强行压到一屏。抖音在发布前滚动至唯一的“发布”按钮，并执行不提交的可操作性检查；按钮被其他弹窗遮挡时不会强制点击，也不会误点侧栏“作品发布”。最终提交仍由原有流程执行，成功仍要求平台回执。

无界面的离线测试保留显式测试尺寸，不改变测试媒体解码环境。

## 封面与失败诊断

封面入口、确认和横封面引导均不额外等待网页跳转，而是沿用已有封面窗口打开、来源检查、确认按钮和关闭状态检查。如果入口点击报告超时，但编辑器实际已打开，就继续验证编辑器，不重复点击入口。

失败DOM新增实际窗口、网页内部尺寸、屏幕可用尺寸、缩放比例、滚动位置及是否模拟视口；抖音开始后也记录这些尺寸。失败阶段记录当前实际操作，修复此前总停留在“等待抖音视频上传控件就绪”的标签。

原有上传总上限、发布确认上限、失败2、成功不重传、5秒额外空闲等待、网盘刷新配置和publiced归档保持。未调整制作管线。

## 验证与失败速度

使用本地页面验证1366宽、540/620/900高时底部按钮可滚动到当前窗口内；按钮被弹窗遮挡时不提交；封面已打开但点击报跳转超时时不重复点击入口。Windows实际有界面浏览器另以1366×728窗口模拟1366×768屏幕扣除任务栏后的空间，读取真实内部高度并验证底部控件。部署版配套141浏览器与完整版运行环境分别检查，未使用真实平台账号发稿。

本次快速失败与上传间隔无关。5秒只发生在两次上传之间，不会缩短当前上传的操作超时；本次触发的是已有的封面点击2秒默认超时，并未进入后面的30分钟上传等待。新修复针对“封面已打开却因等待无关跳转而误报失败”，不把总等待时间缩短成5秒。
