# 多平台第一阶段：登录与 DOM 采集

本阶段在源码中接入小红书、快手、YouTube，保留抖音现有发布功能。新平台尚未启用自动发布，也不会移动媒体文件。

## 使用方式

1. 完全退出书声，再从当前源码启动。第二个工作台名称改为“多平台自动发布”。
2. 顶部“发布渠道”复选框支持单选或多选，选择会保存。只有抖音支持实际发布；包含新渠道时会明确提示尚未接入，不会偷偷仅发布抖音。
3. “查看/配置渠道”下拉框用于切换配置页面，和实际发布渠道勾选相互独立。选择抖音仍进入原面板。
4. 选择新渠道，添加账号备注名称，填写可选的平台账号/YouTube频道标识及媒体目录，保存配置。
5. 点击“登录 / 采集 DOM”，在专属浏览器中手工登录并核对实际账号/频道。YouTube登录后点击“创建 → 上传视频”；其他平台进入视频发布页。
6. 在浏览器中手工选择测试视频、打开封面/合集等窗口。回到采集台选择标签页、采集阶段，点击采集。建议依次保存上传前、上传中、上传完成、标题与正文、封面、合集/播放列表、发布前及异常提示。
7. 采集结果实时写入日志；点击“打开采集报告”查看。可以连续采集，采集本身不关闭浏览器。不自动点击发布，不操作无关弹窗。
8. 点击“我已核对登录账号/频道”只记录用户确认状态，不表示书声已自动验证平台身份或授权。重新使用时仍需核对实际页面。
9. 点击“关闭会话”，等浏览器线程正常结束；关闭主窗口时也会等待线程清理。

采集“发布结果”需要用户自行决定是否手工发布测试作品。本阶段没有自动发布测试操作。Google登录若拒绝自动化浏览器，本阶段不绕过登录验证；保留实际提示再排查。浏览器使用当前系统网络，不自动切换VPN。

## 存储与隔离

- 新渠道配置：`data/multi_platform/accounts.json`。
- 独立会话：`data/multi_platform/profiles/<平台>/<账号ID>/`。
- DOM采集：`data/multi_platform/dom_reports/<平台>/<账号ID>/<会话ID>/`。
- 同一会话的阶段报告与截图由 `session.json` 索引串联。DOM报告保存平台、账号、阶段、frame地址、表单和按钮、可见性与禁用状态、进度和提示、开放Shadow DOM节点。
- 不采集输入框的值，URL移除查询参数；外部来源iframe仅登记地址。关闭的Shadow DOM和原生浏览器权限窗不属于可读取的页面DOM。
- 截图失败时仍保留DOM报告，索引明确无截图；导航失败时浏览器保留，允许手工继续。
- 移除账号仅删除配置项，保留其浏览器目录。

抖音仍使用原 `data/douyin_accounts.json`、`data/douyin_profiles/`、原DOM采集台与原报告路径。本阶段不迁移抖音账号，也不修改抖音上传、确认成功、重试和归档逻辑；独立使用抖音面板时也不受新渠道选择影响。

## 第二阶段边界

自动发布器、各平台真实成功/限额识别、多渠道发布结果矩阵与统一归档将在第二阶段接入。第一阶段新渠道没有任何发布后文件夹，也没有按渠道复制媒体。原抖音单渠道发布仍按原配置归档；未来多渠道发布必须在所有目标确认成功后统一归档。

真实登录后的平台表单验收需要账号持有者操作。开发回归使用临时账号、离屏Qt和本地模拟Chromium页面，不代表三个平台已经完成真实登录或真实上传验收。

本阶段80项本地回归通过（原抖音65项、新渠道15项），主窗口导入检查通过；尚未重新打包安装版本。
