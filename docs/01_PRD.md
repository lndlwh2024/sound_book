# BookAgent v0.1 产品需求文档 PRD

## 1. 产品名称

BookAgent

当前版本：

v0.1 - 原文有声书模式

---

## 2. 产品目标

BookAgent 是一个可重复运行的书籍内容生产工具。

第一阶段只解决一个问题：

> 将 PDF / EPUB 书籍可靠地转换为完整有声书。

产品必须保证：

- 尽可能忠实保留书籍原文；
- 不使用大语言模型改写正文；
- 支持长书处理；
- 支持失败重试；
- 支持断点续跑；
- 支持多种 TTS 引擎；
- 同一本书无需因局部失败而重新生成全部音频。

未来版本将增加：

`MODE_B_DEEP_DIVE`

即完整书籍深度精讲模式。

v0.1 暂不实现。

---

# 3. 目标用户

主要用户：

- 希望将自己的电子书转换为有声书的个人用户；
- 需要批量生产有声内容的内容创作者；
- 需要将合法授权文本转换为语音内容的用户。

用户应确保输入内容符合其所在地适用的版权及使用授权要求。

---

# 4. 核心使用场景

用户准备一本：

- PDF
- EPUB

启动：

`run.bat`

程序显示：

请选择 TTS：

1. Kokoro
2. F5-TTS
3. Azure AI Speech

用户选择一种 TTS 后，程序自动完成：

书籍解析
→ 章节识别
→ 正文清理
→ TTS 切块
→ 语音生成
→ 音频检查
→ 章节合并
→ 整书输出

---

# 5. 支持的 TTS 模式

## 5.1 Kokoro

定位：

轻量级本地 TTS。

特点：

- 本地运行；
- 无 API 费用；
- 优先支持 CPU / CUDA 自动选择；
- 作为默认本地快速方案。

---

## 5.2 F5-TTS

定位：

更高质量的本地 TTS / 参考声音方案。

特点：

- 本地运行；
- 支持参考音频；
- 使用独立 Python 环境；
- 必须考虑 4GB GPU 显存限制；
- GPU 不可用或显存不足时必须产生明确错误信息。

首版不要求自动解决所有 F5 硬件限制。

---

## 5.3 Azure AI Speech

定位：

官方云端稳定 TTS 服务。

特点：

- 使用 Microsoft Azure AI Speech 官方 API；
- 使用官方 Python SDK；
- API Key 不允许写入源代码；
- 支持 voice、rate、volume 等参数；
- 网络或 API 失败时必须支持重试。

不使用 edge-tts 替代 Azure Speech。

---

# 6. 用户体验要求

用户面对的是一个应用：

BookAgent

用户不得感知或手工管理多个 Python 环境。

用户只需要：

`run.bat`

或：

`python app.py`

然后选择 TTS。

以下操作必须由程序内部完成：

- Python 环境选择；
- Worker 调用；
- 模型调用；
- 输出路径管理；
- chunk 状态管理；
- 重试；
- 音频合并。

禁止要求普通用户执行：

`activate`
`deactivate`
或手工切换虚拟环境。

---

# 7. 输入

v0.1 支持：

- PDF
- EPUB

暂不支持：

- 扫描型 PDF OCR；
- DOCX；
- 网页；
- 图片；
- 手写内容。

如果 PDF 没有有效文本层：

程序应识别并明确提示：

`SCAN_PDF_NOT_SUPPORTED`

而不是生成乱码。

---

# 8. 书籍解析要求

程序应识别：

- 书名；
- 作者；
- 前言；
- 目录；
- 章节；
- 小节；
- 正文；
- 后记；
- 注释；
- 附录。

不允许根据 AI 猜测虚构章节。

---

# 9. 正文清洗

允许清理：

- 页码；
- 重复页眉；
- 重复页脚；
- PDF 错误换行；
- 异常空白；
- 明显排版字符。

禁止：

- 改写正文；
- 总结正文；
- 自动润色；
- 删除正常段落；
- 改变作者原意。

---

# 10. 文本完整性

系统必须保存：

- 原始提取文本；
- 清洗后文本；
- 清洗差异统计；
- 原始字符数；
- 清洗字符数；
- 章节数。

若字符数量发生异常变化：

任务进入：

`NEEDS_REVIEW`

不得直接继续批量 TTS。

---

# 11. TTS Chunk

不得简单按固定字符位置硬切。

优先顺序：

章节
→ 段落
→ 句子
→ 最大长度限制

禁止从一句话中间切开。

每个 chunk 必须拥有稳定 ID。

例如：

`chapter_003_chunk_0017`

每个 chunk 保存：

- chapter_id
- chunk_id
- text
- text_hash
- backend
- voice
- speed
- status
- output_file

---

# 12. 断点续跑

这是强制需求。

若一本书有 500 个 chunk：

前 350 个已经成功生成，

第 351 个失败，

重新启动后：

不得重新生成前 350 个。

只有以下情况才重新生成：

- 原文变化；
- text_hash 变化；
- TTS backend 变化；
- voice 变化；
- speed 等关键参数变化。

---

# 13. 音频输出

中间音频优先统一为：

WAV

最终输出：

## 章节级

`chapter_001.mp3`

`chapter_002.mp3`

……

## 整书

`book.m4b`

M4B 应支持：

- 书名；
- 作者；
- 封面；
- 章节；
- chapter timestamp；
- 播放进度。

---

# 14. 音频 QC

至少检查：

- 音频文件是否存在；
- 文件是否损坏；
- 时长是否为 0；
- 是否出现异常静音；
- chunk 是否缺失；
- 章节是否缺段。

统一：

- Sample Rate
- Channels
- 输出格式

使用 FFmpeg 完成最终音频处理。

---

# 15. 状态机

任务状态：

`INGEST`

↓

`PARSED`

↓

`CLEANED`

↓

`VALIDATED`

↓

`TTS_READY`

↓

`TTS_GENERATING`

↓

`AUDIO_QC`

↓

`ASSEMBLED`

↓

`COMPLETED`

异常：

`NEEDS_REVIEW`

`FAILED`

所有 FAILED 状态必须允许恢复。

---

# 16. v0.1 不实现的功能

明确禁止范围膨胀：

- Web UI；
- OCR；
- AI 总结；
- 深度精讲；
- 视频生成；
- 数字人；
- AI 图片；
- 自动翻译；
- 声音训练；
- 用户账户系统；
- 云端任务管理系统。

---

# 17. 验收标准

v0.1 通过标准：

给定一本正常文本型 PDF 或 EPUB：

1. 成功识别主体章节；
2. 成功提取正文；
3. 无明显正文丢失；
4. 可选择三种 TTS；
5. 任意一种 TTS 成功生成章节音频；
6. chunk 失败后可以断点续跑；
7. 可生成章节 MP3；
8. 可生成整书 M4B；
9. 第二本书无需修改程序代码；
10. 用户无需手工切换 Python 环境。
