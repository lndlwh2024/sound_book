# 统一归档规则（2026.10.19.5）

完整版和独立部署版共用 `src/publisher/archive.py`。多平台自动部署、手工上传完成后的归档、扫描清理和旧抖音独立入口均使用相同规则。

## 目录与文件重名

本地制作及Google Drive下载的媒体，完成本任务原有的归档条件后，均进入工作目录下的 `publiced`。不再新建 `published`，不自动搬迁旧目录，也不改写历史报告中的旧路径。

| `publiced` 中的情况 | 完成部署后的处理 |
| --- | --- |
| 没有同名文件 | 使用原文件名归档 |
| 同名、完整SHA-256一致 | 复用已有归档，校验工作文件和归档均未变化后清理工作副本，不再保存第二份媒体 |
| 同名、内容不同 | 保留已有文件，新文件另存为 `原名_重复.扩展名` |
| `_重复` 名称也已存在 | 内容一致则复用；内容不同继续使用 `_重复_2`、`_重复_3` 等，不覆盖 |

字幕随媒体归档。配套字幕名称冲突且内容不同时保留字幕变体；媒体相同时不因此另存相同媒体。孤立字幕不会被覆盖或错误配对。文件变化、被占用、取消或内容校验失败时保留未处理的工作文件，并记录原因。跨磁盘归档先复制至临时文件、校验完整摘要，再完成移动。

Google Drive接口仍只读取和下载。这里的“云盘来源归档”指下载后的本地媒体；不移动、删除或创建Google云端目录和文件。

## 历史补发与增量发布

归档重名判断只影响资产保存，不能用作发布成功的依据。发布仍按“内容SHA-256＋平台＋稳定账号ID”查成功历史。存在同名归档也不能跳过一个尚未成功的平台。

例如：历史视频已在抖音、快手发布，只补发微信视频号时，把媒体复制至绑定工作目录，并仅选择微信视频号。微信视频号成功且满足原归档条件后，已有相同内容的 `publiced` 文件被复用；抖音、快手的成功记录不变。再次放入同内容的视频，微信视频号也跳过上传，不新增尝试或额度。

所选账号的完成范围、自动归档开关、失败与中断保留、最多两次尝试、每日额度、共享云盘下载规则及日期断点均沿用现有实现。无需删除账号、清空账本或重新登录。`reports` 和业务数据目录继续保留。

## 更新与验证

先停止部署、等待上传结束并从托盘安全退出，再替换部署版程序；保留原用户数据目录。完整版重启加载代码。两端版本号统一为 `2026.10.19.5`。

自动化验证使用临时文件、隔离账本和模拟平台，覆盖原名归档、同内容复用、异内容编号、字幕冲突、取消、文件变化、并发名称冲突、跨磁盘失败保留及微信视频号历史补发。完整发布与云盘回归另行执行；不将离线测试描述为真实平台投稿成功。
