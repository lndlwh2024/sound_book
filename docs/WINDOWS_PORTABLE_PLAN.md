# Windows 10 笔记本移植方案（待用户确认）

日期：2026-10-17。本文是方案，不表示已经完成打包或验证 Win10 兼容性。

## 目标与现状

目标设备无需预装 Python、Git、Node 或开发工具，解压后运行“启动书声”。不依赖当前开发机，也不使用现有重要生产服务器。

当前主环境为 Python 3.12.11、PySide6 6.11.2、Playwright 1.63.0；仓库没有现成的 PyInstaller spec 或免安装发行流程。主程序是 PySide6 桌面应用。F5 和 Kokoro 分别调用 `envs/f5`、`envs/kokoro` 的 Python 子进程；因此只冻结主程序不能自动包含全部制作功能。

## 推荐交付方式

优先制作 **Windows x64 文件夹便携包**：随包提供经过验证的私有 Python 运行时、依赖、Qt 插件、FFmpeg/FFprobe、发布浏览器、字体和静态资源。通过专用启动器定位相对路径，不要求系统安装 Python，不修改全局 PATH，不直接复制开发机虚拟环境。

第一阶段可以保留内部 Python 运行时启动主程序，以减少 `__file__`、子进程和路径兼容改动；如后续需要 EXE 外观，可增加启动器或以 PyInstaller 文件夹方式冻结主程序。F5/Kokoro 仍须单独打包运行时与依赖。避免把模型、浏览器和多个运行时塞入单个自解压 EXE。

分为两个可选包，待确认笔记本用途与硬件后选择：

| 包 | 范围 | 主要依赖 |
| --- | --- | --- |
| 发布包 | 云盘下载、断点补扫、去重、多平台发布 | 主运行时、Qt、发布浏览器、媒体检查工具 |
| 完整制作包 | 发布包加文字/电子书处理、TTS、字幕和视频制作 | 另加实际使用的制作后端、模型、词典、字体和对应运行时 |

本地 TTS/模型是否可用、速度与包体大小取决于笔记本 CPU、内存、显卡及实际模型；不承诺无 NVIDIA 显卡也能保持当前 GPU 制作速度。CPU 路径或在线后端只能在功能确实支持且实测后提供。

## 必须完成的适配

1. 固定 Windows 10 x64 的最低系统版本，核对 Qt、Python、浏览器与所用 AI 依赖的支持范围，在目标 Win10 或等效干净环境验收；不能仅凭在当前电脑运行成功就宣布兼容。
2. 统一程序资源、用户数据和输出目录；移除开发机 `H:`、虚拟环境绝对路径与快捷方式依赖。用户选择新的本地目录，日志、缓存和配置写入可写目录。
3. 为子进程定位便携的主/F5/Kokoro 解释器和 workers；依赖与模型按后端隔离，不在新电脑临时下载不受控的最新版软件。
4. 内置匹配版本的 Playwright 浏览器或经过验证的可用浏览器策略，不假设笔记本已经安装浏览器驱动。内置 FFmpeg/FFprobe，并核对发行许可、编解码和字体需求。
5. 必要系统运行库可在安装说明或启动检查中提示；显卡驱动属于目标系统依赖，不打包复制开发机驱动。
6. 配置、更新包和用户数据分离；提供版本号、文件校验值、启动自检与回滚说明。更新不覆盖输出媒体、历史记录和用户授权。

## 账号与历史迁移

- Google 授权令牌由当前 Windows 用户 DPAPI 加密，不能把旧机 `credentials.dpapi` 当作可跨电脑使用的授权；新电脑需要重新在 Google 网页授权。
- 平台账号在新机重新登录并核对平台身份；不承诺直接复制浏览器登录目录就能保持有效登录。
- 如需继承去重、日期扫描断点、上传额度和账号绑定，应在旧机停止相关任务后一致性备份相关数据库及账号配置，保留账号 ID，并适配新机目录。云盘文件版本与扫描断点包含本地目录作用域，换路径后需要明确迁移映射，不能直接改路径后宣称已继承。
- 不默认打包用户视频、书籍、API 密钥、Google 令牌或平台浏览器会话；必要的个人密钥由用户在目标机配置，不上传 GitHub。
- 两台电脑若同时处理同一账号，当前本地去重与额度并非跨机器同步；迁移验收时先保持单机运行，跨机并发需另行设计。

## 验收后再交付

在无开发环境的 Win10 x64 上检查：启动与中文显示、目录及磁盘权限、云盘授权/目录选择、总开关、日期补扫、下载校验、重启去重，以及经用户明确选择的制作后端和平台发布流程。先离线/隔离验证，真实投稿单独验收。

## 确认事项

用户需确认“发布包”或“完整制作包”，并提供 Win10 系统版本、是否 x64、内存、显卡型号及可用磁盘空间。确认后才开始便携运行时、启动器及安装包的实现；当前 Git 推送仅包含源码、测试和本方案。
