## Playwright 兼容策略

news 的现场运行证明这台 Win10 存在可用的 Playwright/浏览器组合。因此不将升级 Windows 作为前提，也不再笼统判断 Win10 无法运行 Playwright。

实施时先核对 news 使用的 Playwright 版本、语言绑定（Python/Node 等）、浏览器版本与启动方式。以该已验证组合为兼容性依据，再验证书声需要的上传功能。不能仅凭 news 可运行，就认定当前开发环境 Python Playwright 1.63.0 也一定兼容。

书声使用独立私有 Python 运行时、依赖、浏览器 profile、日志、账号配置和数据库，不修改 news 的安装目录、运行时、进程、浏览器 profile 或现有发布任务。若同一浏览器程序可安全复用且版本匹配，可只读使用其可执行程序；不共享登录 profile，不接管 news 正在运行的浏览器。默认仍按书声私有浏览器路径交付，避免共同缓存更新影响另一应用。

Google 官方授权仍由系统浏览器中的用户登录/同意完成，不代替用户选择账号或提取 news 的授权信息。

官方最新版 Playwright 的支持矩阵与既有版本能否现场运行是两个概念；如需选用其他版本，固定完整依赖组合，并记录维护和兼容性边界。官方参考：[Playwright 系统要求](https://playwright.dev/python/docs/intro#system-requirements)、[浏览器版本管理](https://playwright.dev/python/docs/browsers)。

## 保留与排除范围

保留账号矩阵、四个平台登录/DOM、共享云盘连接、各账号目录绑定、本地目录直接发布、日期断点补扫、下载校验、平台账号级去重、每日额度、重试、发布日志、成功 publiced 归档和重复 _重复 后缀。

使用独立发布入口和窗口，直接加载发布模块；不只是把完整主窗口的制作标签隐藏。

不加载或打包视频生产、TTS、字幕对齐、混音、插画、视频合成、F5/Kokoro、Torch/CUDA、模型及制作专用 workers。不执行转码，无需独立显卡。保留当前发布器实际使用的 FFprobe 时长检查；其他媒体二进制仅按审计结果携带。

## 资源预算与并行方式

以下为设计目标，必须通过打包结果与 X230 实测核对，不能当作已测占用：

| 项目 | 方案 |
| --- | --- |
| 书声浏览器并发 | 最多一个发布浏览器进程组，平台/账号按顺序执行；预检与手工登录也避免并发打开多个浏览器 |
| 下载并发 | 最多一个下载任务，流式写入文件，不将整段视频读入内存 |
| 与 news 共存 | 独立 profile 与进程；先实测两者同时运行，若出现内存压力，配置错峰发布，不默认停止或改动 news |
| 程序与依赖 | 便携包解压后目标控制在 3 GB 内，实际大小以构建结果为准；不携带模型与多个 TTS 环境 |
| 下载/归档占用 | 默认计划上限 8 GB，包含待发文件、临时下载及 publiced 归档，不只计算临时缓存 |
| 最低剩余磁盘 | 默认计划保留 5 GB；按云端文件大小检查下载后的空间，空间不足暂停新下载并明确提示，已下载内容仍可发布 |
| 日志 | 滚动保存，计划最多 100 MB；账号去重/断点数据库属于业务记录，不按日志规则清除 |

20 GB 估计可用空间可以作为轻量发布包的初始部署预算，不能视为允许无限下载。归档只是移动，不释放磁盘；达到空间阈值时暂停下载，不擅自删除原视频、归档或业务历史。单个媒体过大时明确提示所需空间，不无限尝试。

不承诺现阶段精确 RAM 占用。验收记录书声空闲、下载、单平台上传以及与 news 并行时的总内存和响应情况。浏览器有多个内部进程，“单浏览器”不等于单进程。

### 与 news 错峰（用户补充于2026-10-17）

用户说明 news 的 Playwright 负载主要集中在北京时间每天08:00和20:00，书声可错开这两段高峰。截图中约20:04和20:11的报告时间只能作为已知负载参考，不能据此认定所有 news 任务结束时间。

建议默认避让窗口为 **07:30–09:00、19:30–21:00**（北京时间，可配置）；书声自动任务可运行窗口为 **09:00–19:30、21:00–次日07:30**。这些时间为方案建议，未创建任何系统或聊天定时任务，尚未在客户端实现。

- 到避让窗口停止发起新的云盘扫描、下载、发布预检和上传；按现有安全边界结束在途任务。不能强杀正在投稿的浏览器或将不确定结果直接记为成功。
- 已开始上传可能持续超过计划边界；预留缓冲后仍须现场核对，不能承诺仅凭时间窗口完全消除重叠。若需严格不重叠，可在后续明确取得 news 完成信号后再启动书声，而不是擅自控制 news。
- 完成收尾后关闭书声持有的发布浏览器，保留账号 profile、OAuth授权、队列与账本；等待期间低频唤醒，不不断重启浏览器。
- 离开避让窗口后，从日期断点继续补扫并依序发布；当天上传额度、账号开关、全局云盘开关和暂停操作仍优先生效，不能因时间到了绕过用户暂停或启动已停止任务。
- 错峰策略只控制书声，不结束、修改或接管 news 的浏览器和任务；设置按北京时间计算并正确处理跨午夜窗口。

## 便携包与界面

提供 Windows x64 文件夹便携包，附启动入口、私有 Python、Qt、必要发布依赖、浏览器及资源，用户无需自行安装 Python、Git、Node 或编译工具。不复制开发机的虚拟环境；固定相对路径并移除 H: 开发路径依赖。

界面只保留发布工作区；账号矩阵、共享云盘接入、保存和部署操作常驻。针对 X230 实际分辨率适配；如为 1366×768，使用紧凑分组与横向标签，不引入配置表单滚动条。日志和内容窗口可以滚动。

程序更新与用户数据分离，提供版本号、校验值、自检和回滚说明；不覆盖用户媒体、配置与历史。启动时检查实际可用磁盘空间和必要系统运行库，不修改系统全局 PATH 或 news 的设置。

## 账号与历史迁移

- Google 令牌绑定当前 Windows 用户 DPAPI，新机重新网页授权，不直接复制旧 credentials.dpapi 充当可用连接。
- 发布平台在新机重新登录并核对身份；不默认复制另一客户端的浏览器登录目录。
- 迁移书声去重历史、日期断点和账号绑定前先停止原机任务，一致性备份数据库/配置，保留账号 ID，并映射新本地路径。版本键和断点包含本地目录作用域，改路径必须同步迁移相关记录。
- 不默认携带用户媒体、API 密钥或平台会话；不上传这些内容到 GitHub。
- 完整制作版留在原机，X230 执行发布。同一发布账号先只由一台书声执行任务，避免两份本地账本导致重复投稿。此限制不等于要求退出不相关的 news 任务。
