# 书声发布版：Windows 10 22H2 x64 交付方案

修订及开发确认日期：2026-10-18。**状态：用户已确认开发，首个发布版候选实现与构建已完成；干净Win10和X230实机验收待进行。** 当前开发机未注册自启任务，未在目标机部署或执行真实投稿。2026-10-17关于20GB可用空间、依赖现有news环境及暂缓整个项目的描述已被本版替代。

## 已确认设备与交付范围

- ThinkPad X230，Intel i5-3230M 2.6GHz，8GB内存，无独立显卡。
- 目标系统明确为 **Windows 10 22H2 64位**；此前“Win11专业版”的描述以本次确认更正。
- 刚重装的干净系统，可用空间约 **90GB**；没有Python、旧news客户端和旧Playwright环境，不假定存在Git、Node、FFmpeg或相关运行库。
- 保留完整版现有发布渠道：抖音、小红书、快手、YouTube，沿用现有账号登录/身份核验、DOM采集、上传和平台确认流程；不扩大完整版当前的媒体类型支持范围。
- 保留Google Drive共享授权、每账号目录绑定、日期断点补扫、流式下载及校验、同范围下载共享、账号级去重、额度、重试、发布日志和收尾归档。
- 不包含制作入口、TTS、模型、Torch/CUDA、字幕对齐、插画、混音和视频合成。使用独立发布入口，不通过隐藏完整版制作标签实现精简。
- 需要登录Windows后自动启动，并在已完成首次配置、授权与登录的前提下恢复云盘监听和自动部署。

## 干净系统交付与兼容性

交付Windows x64文件夹发行包，附双击启动入口、独立Python运行时、Qt界面、发布依赖、与Playwright版本严格匹配的私有Chromium、时长检查实际需要的FFprobe，以及必要字体/图标/配置模板。无需目标机预装Python、Git、Node或单独执行Playwright安装命令；不直接复制开发机虚拟环境，不依赖H:路径或开发机PATH。

在构建环境下载和校验私有浏览器，随发行包交付；目标机不靠首次启动临时下载浏览器。Playwright自身需要的驱动运行时一并携带。Google首次授权仍通过系统默认浏览器交互完成，与发布用私有浏览器分开。目标机保留系统自带Edge即可，无需另外安装Chrome；自动上传默认使用发行包内经过Win10实测的私有Chromium，不依赖系统Chrome/Edge版本。

必要的微软VC运行库先检测；确有缺失时采用官方安装包补齐，可能需要一次系统权限确认。除启动项和必要运行库外不要求安装业务服务，不部署数据库服务器、Web服务器、Docker或Windows后台服务。

**Win10必须单独验证。** 当前Playwright Python官方系统要求为Windows11及以上，不能将开发机现用版本直接标记为Win10受支持；旧news环境已删除，也不能再引用它作为现场兼容证明。实施时选定并锁定经Win10 22H2实测的Python、PySide6、Playwright及浏览器完整版本组合。优先保持受维护的浏览器；若必须使用旧组合，记录明确版本、维护边界和升级路径。未在干净Win10与X230上通过前，不声明可交付；若无可接受组合，再反馈调整方案，不静默降级。

参考：[Playwright系统要求](https://playwright.dev/python/docs/intro#system-requirements)、[浏览器与库的版本配套](https://playwright.dev/python/docs/browsers)。

## 网络条件与另案边界

用户确认：X230访问Google Drive需要另外解决网络连通性。VPN／Trojan客户端缺失DLL的问题**另案处理，本次不排查、不修复、不随书声打包**，也不承诺书声附带的运行库会修复VPN客户端。另案待办见 [BUGLIST：VPN-CLIENT-001](BUGLIST.md#vpn-client-001x230网络客户端缺失dll)。

书声不捆绑VPN、订阅、节点或代理服务，不自动修改系统代理、路由及其他客户端。正式Google联调前，目标机需要已经具备可用的网络访问条件；网络客户端问题不阻塞发布版入口和本地发布的离线适配，但会阻塞目标机Google Drive及YouTube的在线验收。

发布版启动自检应分别报告系统浏览器授权页、客户端Google API访问、媒体下载和各发布平台的连通性。不能仅凭系统浏览器能打开Google就判定书声API请求及私有发布浏览器全部可用。Google不可达时仅暂停云盘同步并按退避策略等待，保留绑定、日期游标和文件；具备网络及登录条件的其他平台仍可发布已下载本地文件。恢复后从断点继续，不清空历史，不自动重新授权。

## 资源与存储策略

以下为初始设计目标，实际包体、RAM和耗时须以构建及目标机实测为准。

| 项目 | 修订方案 |
| --- | --- |
| 程序包 | 解压后目标不超过3GB，是否达标由构建产物确认；不携带制作模型和多套浏览器 |
| 浏览器并发 | 最多一个发布浏览器进程组；四平台及账号顺序执行，预检、登录/采集与上传互斥 |
| 下载并发 | 一次一个文件，分块写入磁盘，下载可与当前单浏览器上传并行；内存紧张时降低重叠 |
| 媒体空间预算 | 待发布、临时下载及归档合计默认上限30GB，可配置；不能只统计临时文件 |
| 最低剩余磁盘 | 默认保留10GB；下载前同时校验媒体预算及下载后可用空间，不足则暂停新下载，已下载内容仍可发布 |
| 日志 | 滚动保存，初始上限100MB；账号账本、日期断点和去重记录不按日志规则删除 |
| 归档 | 沿用publiced / published及重复标记；归档移动不释放磁盘，不自动删除视频、归档或业务记录 |

约90GB可用空间已足够制定宽松的发布版部署预算，但不代表允许无限缓存。发布版已实现默认30GB媒体预算及10GB剩余空间保护，在运行设置中可调整；新下载前统计待发、临时文件及归档，下载期间检查剩余空间，不自动删文件。记录空闲、下载、各平台上传和连续运行的内存/CPU/磁盘占用，不承诺尚未实测的精确RAM数值。

旧news环境已不存在，原08:00/20:00强制错峰不作为本版默认限制；保留可配置运行时段的设计。如以后恢复news，再使用独立运行时与profile，并根据实际负载启用错峰。当前不创建错峰或聊天定时任务，也不控制其他程序。

## 首次初始化

1. 解压到固定且当前用户可写的位置，通过自检确认运行库、私有浏览器、FFprobe、目录写权限和磁盘空间。
2. 导入Google桌面OAuth客户端配置，使用笔记本当前Windows用户完成一次网页授权；开发机令牌不能直接作为新机授权使用。
3. 分别登录需要启用的四个平台账号，核验实际身份并采集/验证对应DOM；保留全部渠道不等于必须同时启用四个平台。
4. 选择各账号云盘系列及本地目录、媒体类型、平台参数、每日额度和归档选项，执行一次用户确认的连接/下载与发布验收。
5. 保存自动运行配置、注册登录自启入口；仅对用户已明确启用并验证过的账号自动恢复。

首次Google同意页面、平台登录、验证码和身份异常都需要用户处理；自启动不能绕过这些步骤。没有预装开发环境不会影响完成以上初始化。

## 登录自启与自动恢复

采用Windows任务计划程序，在当前用户**登录后**延迟约60–120秒启动发布版，运行于交互式桌面，默认普通用户权限。计划任务拒绝重复实例，客户端另加单实例锁；手动启动与自启重叠时只激活已有窗口。

“开机自启”指登录Windows之后启动。未登录桌面时，不以系统服务或无人登录任务运行GUI浏览器，不配置自动登录、不保存Windows密码。如设备重启停在登录页，需先登录Windows。

启动后依次执行：

1. 加载业务配置、账本及自动运行意图，检查数据可读性和文件夹有效性。
2. 网络未就绪时按15/30/60秒递增重试，最长间隔5分钟，界面显示等待状态；不反复弹窗或重启浏览器。
3. 独立核验Google凭据与API连通性，条件具备后按已保存日期断点补扫至北京时间当天；同范围文件只下载一份，其他绑定按各自范围处理。该分支等待网络时，不阻塞已有本地文件的发布预检。
4. 核验本次所选平台账号登录、身份、配置和DOM，按完整版的预检门槛恢复顺序部署。缺少条件不绕过，显示需要登录/配置等原因。
5. 所选账号成功后按既有规则归档，并执行新增副本收尾；每日额度、账号开关及暂停状态持续生效。

自动恢复必须区分运行意图与当前进程状态：

- 保存“登录自启、自动恢复监听、自动恢复部署”选项，以及所选平台/账号ID、目录和运行参数。
- 系统重启或异常退出后，仅在上次允许自动运行时恢复；用户明确停止或暂停后保存该意图，不能下次启动自动反向开启。需提供单独的“退出但保留下次自动运行”路径，避免退出窗口与停止业务混为一谈。
- Google授权失效或平台登录失效时暂停受影响分支，提示重新连接；不自动删除授权/目录或冒用其他账号。Google断开不应阻止已经下载文件的本地发布。
- 对上次中断且没有明确成功确认的投稿保留文件与结果证据，按既有核对/重试策略处理；无法判断时要求核验，不能仅凭重启就将它当新文件直接重传。
- 自启/恢复阶段不隐藏错误；可先显示窗口，稳定后提供托盘最小化设置。不得把浏览器授权等待显示成连接成功。

如要求长时间无人操作运行，需在目标机配置通电时不自动睡眠，保持用户登录；锁屏/解锁、睡眠恢复和断网恢复都纳入实测，不假定关闭笔记本上盖后仍可上传。不自动修改系统电源设置。

## 配置、账号与历史迁移

程序版本与用户数据分离。建议程序目录与独立的数据目录/媒体目录相分离；更新不覆盖配置、账号profile、OAuth凭据、媒体或账本，附版本号、校验值、备份及回滚说明。

Google令牌采用新机当前Windows用户DPAPI保护。平台账号在新机重新登录；不复制开发机的浏览器会话或旧news数据。Google客户端配置在本机初始化，不把真实令牌、客户端凭据JSON或会话文件提交GitHub。

如沿用原机发布账号，优先一致性迁移原书声账号ID、成功账本、额度记录和日期断点；迁移前停止原机相同账号的部署，并备份数据库。映射新目录时同步迁移下载作用域与日期游标，防止改路径造成历史失效。已经成功的版本保持消费状态；尚未成功且没有携带本地媒体的下载记录，必须重新排队并校验云端内容，不能因为旧记录写着DOWNLOADED就永久跳过。迁移媒体本身为可选项，不能因此丢失待发内容。

用户已明确确认不同电脑可以同时运行书声：原机完整版制作并同步云盘，X230发布版下载并发布；不同发布账号可以分配给不同电脑。同一平台同一发布账号只由一台书声自动部署，避免独立账本并行造成重复投稿；当前没有跨电脑锁或跨机共享去重。相同Google Drive可供两台读取。单台电脑不要求运行多个实例，发布版已加入单实例和唤起已有窗口。恢复另一程序news不影响这条针对同一书声账号的约束。

界面沿用已确认的公共配置、下拉账号选择及目录绑定/部署配置分组；以1366×768作为兼容测试档位之一，实际X230分辨率和缩放由自检采集。通过分组与布局适配展示参数，不引入配置表单滚动条；日志和多行文本允许滚动。
