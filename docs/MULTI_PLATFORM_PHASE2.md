# 多平台发布第二阶段

本阶段接入 YouTube 上传与发布，并提供抖音、YouTube 共用的多目标任务、结果统计和归档策略。小红书、快手保留独立账号和 DOM 采集，尚未开放实际发布；选择未支持的渠道会提示补齐现场 DOM，不会忽略它并归档文件。

## 界面与账号

左下部署操作区在“启动部署”按钮上方勾选本次发布渠道，右上角“查看平台”下拉列表切换查看账号和参数。查看平台不会改变发布渠道选择。四个平台共用一个 `PlatformAccountPanel` 类和一组渠道控件，切换时同步移到当前面板的部署区。所有平台采用同一深色主题、账号列表、配置滚动区、保存按钮、队列和日志布局；账号区域保留两条账号的完整显示空间。点击启动时再勾选本次部署账号；选择后复制配置固定本次目标，不随界面切换改变。

## 共用账号配置

四个平台都提供账号备注、平台真实昵称、登录/获取昵称、媒体目录、视频/音频/图片监听选择、账号启用、自动归档及手工核对备注。统一保存、目录扫描与部署筛选；未勾选任何媒体类型时不会偷偷恢复视频选项，启动会提示先选择类型。列表定时刷新保留当前选中文件。

“登录 / 获取平台昵称”使用同一浏览器会话和回写流程，登录后周期性读取本平台的本人账号区域；也可点“读取平台昵称”。识别成功后更新昵称与显示名称，保留原账号 ID、浏览器登录目录和发布身份。识别不到或出现多个候选时保留原备注，不用页面标题或作品作者代替；手工确认登录与自动获取昵称分别记录。网站变动可能需要按现场 DOM 补充本人区域选择器，当前测试是本地页面验证，不能替代实际登录验收。

平台独有参数放在“本平台发布参数（点击展开）”：抖音保留合集、话题标签；YouTube 保留标题规则、说明、播放列表、公开范围、儿童设置、AI 声明和缩略图。实际 YouTube 频道 ID 直接显示在配置上部，用于上传前核对实际频道、防止串号；昵称不能替代频道 ID。小红书和快手继续保留发布尚待现场 DOM 验证的限制。

媒体监听类型在各平台一致，不代表网站接受所有类型。YouTube 当前发布器只支持视频，选择独立音频或图片时保留文件、记录永久跳过，不拉起浏览器、不重试。抖音继续复用原发布器。

所有面板读取同一 `ChannelAccount` 配置契约，由 `PlatformAccountRepository` 统一操作。旧抖音存储仅作兼容适配，账号 ID、登录目录和历史账本不迁移；旧抖音独立配置面板已移除，主窗口没有第二套配置或发布入口。

新平台账号使用独立浏览器目录，不复用抖音登录状态。YouTube 的账号备注不代表实际频道：上传前校验实际频道 ID 与配置是否一致，不一致则停止该账号，不上传文件。

## YouTube 配置与验收

1. 勾选 YouTube，在“查看平台”下拉列表选择 YouTube，选择已采集的账号，绑定媒体目录。
2. 在配置上部核对实际频道 ID（UC 开头）。登录后可自动读取；能从该账号 DOM 唯一识别时也会预填，仍需保存配置。此次采集中的账号备注与页面频道名称不同，因此以频道 ID 校验。
3. 展开“本平台发布参数”，设置标题规则、说明、播放列表、公开范围以及是否面向儿童。说明留空则清空说明；是否面向儿童必须明确选择。AI 内容声明由用户配置，不自动推断。
4. 封面可使用平台默认，或提取视频首帧提交到缩略图文件控件。没有采集过播放列表选择弹窗与自定义缩略图完成状态，这两项需要真实页面验证。
5. 保存配置、启动部署并选择账号。首次建议仅使用一个短测试视频验收。

依据本次实际 DOM 定位标题和说明，避免两个编辑器同为 `textbox` 导致写错位置。上传完成需同时满足进度结束、检查完成和有效视频 ID；点击发布后进入内容管理核对该视频的标题及配置公开范围，确认后才记录成功。视频链接或“已保存为私享视频”本身不代表公开发布成功。

目前本地上传向导、等待进度、公开范围确认、停止流程已验证；真实 Studio 的初始上传菜单、最终内容列表、播放列表弹窗和缩略图流程仍需验收。遇到页面结构变化会记录失败或未确认及诊断报告，不直接归档。

## 文件、重试与账号限制

同一文件要发布到多个渠道，应让对应账号绑定同一个媒体目录。不同目录中的文件各自建立发布目标。每个文件展示四个渠道的结果，悬停查看账号、状态及原因；“核对各渠道结果”可查看详细结果，并在用户核对平台记录后确认成功或允许重试。

普通失败先搁置，首轮全部处理完后集中重试一次；永久拒绝及超过时长的文件不重试。投稿上限立即停止该账号后续任务，其他账号继续。当天的账号限额状态会持久保存，重启不会立即重复投稿。

结果未确认的文件不会盲目再次发布。YouTube 能用已记录的视频 ID 核对内容管理状态；无法确认则留待人工核对。旧抖音日账本缺少本阶段所需确认信息的记录同样要求核对，以避免重复投稿。

文件正在写入时不上传；文件内容变化时不沿用之前成功结果。提交发布前保存待确认记录，降低中断后重复提交的风险。

## 归档与任务报告

不创建四份发布目录。所有已登记目标成功且都启用自动归档后，源文件只移动一次到原目录的 `published/`。任何目标失败、未确认、取消或尚未执行，源文件保留；重启仅补齐未成功目标。缩小下一次渠道选择不会提前归档仍有未完成目标的文件。

统一任务报告位置：`data/multi_platform/publish_reports/publish_task_*.json`。一次启动一份报告，实时更新，结束时写入统计；报告包含文件名、目录、大小、修改时间、文件摘要、各平台账号结果、每次尝试、原因、成功与失败文件列表和数量。目标成功数与源文件全部目标成功数分开统计，未确认、取消单独列出。

持续监听任务在停止前保持同一报告；点击上传所选文件则完成该批后结束。独立 DOM 诊断 JSON 和截图仍按事件保存，用于定位页面故障，不是逐文件发布任务报告。

单选、多选、抖音及其他渠道的手动上传全部使用统一任务，不再按是否存在历史账本切换到原抖音守护。抖音仍调用原浏览器发布器，去重、重试、结果统计和归档由统一任务负责。“查看报告”也统一指向上述任务报告目录。

## 统一去重

去重键为整个文件内容的 SHA-256、平台标识、账号 ID，记录持久保存于 `data/multi_platform/target_ledger.json`。改名或移动目录后，内容相同且同目标已成功时跳过；同名内容改变视为新文件；不同平台和账号分别记录，允许分别投稿。未确认结果不会当作普通失败重传；提交边界后发生连接异常也保留未确认状态，需平台核对。删除账本、删除账号后创建新账号，或重新编码改变文件内容，将无法沿用原去重身份；它不识别画面或语义相似的视频。

现有抖音旧 MD5 账本会按当前媒体目录 `reports/` 中的记录检查；匹配历史成功时保留待核对，不自动重传，也不把缺少确认依据的旧记录直接当作成功。账本不存在的历史投稿或另一个设备上的投稿，不会自动从平台补齐。

旧账本兼容带 UTF-8 BOM 的文件。无法读取或结构损坏时保留原文件，日志显示账本路径与具体原因，仅阻止对应账号，其他目标继续。媒体消失、变化或被占用单独记录为文件问题，不再误报账本错误。账号配置与旧抖音账本采用临时文件替换方式保存，避免直接截断正在使用的记录。

## 验证范围与交付

全部平台测试使用临时账号目录与本地页面，不访问真实账号，不执行实际投稿。源码已修改，未打包，也未替换外部运行目录中的应用。重启源码运行版本才能使用本阶段功能；正式发布前需进行真实平台验收。
