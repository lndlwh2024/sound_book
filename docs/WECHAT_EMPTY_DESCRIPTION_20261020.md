# 微信视频号空描述核验修复

统一版本：2026.10.20.9。完整版和独立部署版复用同一修复，描述继续默认留空，不增加配置项。

## 诊断包4的实际停点

现场版本为2026.10.20.8。任务813c57cc中，纸张对折、早晨身高两个文件分别尝试两次，四次均在“核对视频描述”5秒超时。短标题、位置、合集、发表尚未执行；后续六个文件因用户停止而未执行。日志中的当日成功0、上限15、剩余15正常，失败没有消耗成功发布名额。

截图中的视频描述区域看起来为空，旧代码却主动清空并要求富文本编辑器的innerText精确等于空字符串，将不需要填写的字段变成了阻断条件。旧DOM采样只专门匹配contenteditable="true"，未采到现场描述编辑器，缺少其原始文本，因此旧诊断不能确定具体残留字符。按用户要求取消描述处理，无需依赖描述编辑器内部的空白表示。

## 修复行为

视频描述保持平台默认空值，不填写、不清空、不等待、不核对，不增加配置项，不再成为发布前置条件。上传完成时的表单就绪判断也改为检查实际使用的短标题输入框，描述编辑区不存在、不可编辑或含不可见光标标记均不会阻塞后续步骤。短标题继续按输入框实际value严格核对，保留16字符及标题标点规则。

失败DOM采样覆盖空属性、true、plaintext-only等编辑区，补充原始textContent、innerText及非文本内容是否存在。这些信息仅用于诊断采样，不参与发布门槛判断，不填写编辑区或替代正常浏览器点击。

描述通过后继续现有短标题、不显示位置、合集、上传完成确认和发表流程。视频已上传不是发布成功，仍须本次真实投稿回执或平台明确成功提示。上传状态、无进展及总时限、失败2、成功去重、每日成功数量、publiced归档和5秒空闲等待保持。抖音及其他平台的网页发布步骤、制作管线保持。

## 验证与现场复测

本地真实浏览器测试覆盖描述编辑区缺失、禁用、不可编辑及含不可见光标标记时继续配置短标题；诊断包含原始编辑区；普通页面和嵌套页面的完整发表模拟。检查描述没有收到输入操作，提交请求全部由本地测试页面接收，不向真实平台投稿。

更新后原账号和登录继续沿用；选择需要的微信视频号文件执行“手动上传所选媒体”，可为失败2开启新一轮尝试。首次现场复测仍需确认位置、合集及发表后的真实结果；如果再次失败，新诊断会保留更完整的编辑区信息。
