# 2026-10-18 上传与日志问题修复

组件版本：2026.10.18.1。适用于完整版发布工作区及独立发布版。既有发布报告、成功记录、额度、媒体和云端草稿均保留。

## 已确认原因

- 本机任务报告起止时间为北京时间2026-10-18 01:55:21—12:05:52。抖音失败记录均为上传页 `domcontentloaded` 导航10秒超时，发生在选择文件前；不是平台已接受后又错误记失败。
- YouTube失败发生在选帧环节。保存的截图中实际弹窗已打开，DOM为带名称“从视频中选择一帧画面”的 `tp-yt-paper-dialog`；旧代码只等待另一个自定义标签，导致误报没打开。上传文件后自动保存的草稿未能走到发布步骤，重试又新建草稿。本机报告记录了3份不同内容的6个草稿ID，其中一份本地同内容副本重复出现在队列，不能把4行都当4份独立内容。
- “失败2仍不断重试”的已确认行为包括每轮扫描先调用结果核对，再检查重试上限，导致重复开浏览器。旧策略在新任务中还会清空失败预算。已改为跨扫描、重启保留上限，且先检查上限再决定是否打开浏览器。
- 两个同日期文件夹由外部写入端产生，用户已确认交由另一个agent修复。书声Drive接口维持只读；已加遍历所有同日期目录的容错。只读在线验证成功读到2个当天目录、7个条目，其中5个视频。

## 修复行为

1. 抖音导航等待主文档响应，上限45秒；再等待实际视频上传控件，上限90秒。登录跳转或非创作者域名不选择文件，错误保留具体阶段。
2. YouTube按实际弹窗角色与名称识别选帧窗口，并兼容旧自定义标签；等待上传处理完成后再选择帧，记录候选帧、可操作帧和图片加载数。
3. 获得视频ID后立即保存草稿检查点；即使随后页面异常退出，也保留刚保存的ID。重试打开相同视频ID继续编辑，不重新选择本地文件。已经开始传输却尚未取得ID、或提交但未确认成功的情况暂停等待核验，不当作成功，也不盲目创建新投稿。
4. 同账号同内容两次上限跨重启保留；失败2不再打开核对/上传浏览器。登录、配置或额度受阻且尚未开始传输时不消耗上传尝试。只有选择文件并确认的手动重试可以开启新一轮，保留原失败证据及草稿ID；明确的本地成功回执仍可离线恢复，不重新发稿。
5. 日志底部按平台切换，保留公共/云盘及全部页；按北京时间精确到秒，记录账号、文件、任务、阶段、结果。新增网络失败、HTTP错误、页面脚本/控制台错误、缩略图就绪状态；不记录Cookie、令牌或URL查询串。
6. 日志JSONL独立落盘并有界轮换，任务报告不再只保留每次尝试最后100条消息；支持导出，最近历史任务按实际已有时间戳回放。同一任务/尝试的重复文件记录只回放一次。
