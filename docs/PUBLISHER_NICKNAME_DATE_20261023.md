# 多平台昵称同步、视频日期与跨日队列

版本：2026.10.23.2。部署包标签：`20261023-nickname-date`。

## 昵称是可选信息

启动预检及上传页统一检查实时登录与上传入口，不再要求昵称非空或与本地旧昵称相同。各平台打开上传页和准备发布时尝试读取本人账号区域；读取到新昵称就同步本地平台昵称及默认显示名。手工备注保留，稳定账号ID、浏览器目录、YouTube固定频道ID、额度与已发布账本不随昵称改变。

昵称读取、保存或同步失败只记录日志，继续原上传流程，不消耗额外尝试次数。后台通过稳定账号ID发送昵称更新，界面线程仅保存对应账号，不切换当前选择、不覆盖未保存的目录编辑，也不恢复已经删除的账号。

本人昵称区域不参与上传状态文字扫描，避免昵称包含“上传中”等词时被误当成尚未完成的上传进度。

登录失效、安全验证和固定频道ID不符仍会阻止发布。视频号已有正式成功回执按稳定账号与独立目录识别，不再因为回执上的旧昵称不同而判为无效；仍严格要求正式发表成功证据，不能把草稿或超时算成功。

## 跨日待发队列的完成条件

**该文件所需平台全部成功，并完成统一归档，才算完成并退出待发队列。**

- 任一平台失败、待核验、未执行，文件跨日继续显示；其他已经成功的平台跳过，不重复上传。
- 全平台成功但关闭归档、归档被占用或移动失败，文件仍显示。报告区分“已全部发布”和“已完成归档”。
- 手动选择全平台成功但仍在原目录的文件，只执行归档，不打开上传浏览器。
- 归档后源文件移出监视目录；过期的异步目录快照也不能把已经移走的文件重新插回队列。
- 日期变化不清除成功记录、重置次数或隐藏未完成文件。各平台成功计数仍按发布成功计算，归档失败不把成功投稿改成失败。

“灯泡”诊断记录中，22日三家平台成功，视频号09:41保存为待核验，23日仍是同一任务ID。用户确认其实际已完成，因此应核对、纠正当时的程序记录；本版不会仅凭日期、文件名或超时自动伪造成功。部署机的真实待核验记录应在作品列表核对后通过“运行设置→核验中断投稿”登记结果，再统一归档。

## 视频日期列

右侧队列显示：序号、视频日期、文件名、文件大小及已选择平台状态。完整版原有类型、修改时间列继续保留；部署版仍按原布局隐藏这两列。

“视频日期”是下载时的云盘日期目录，如 `2026-10-22`，不是本机修改时间或文件名中的日期。悬停可看云盘来源日期和下载完成时间；下载进度及日志也带日期。

日期写入独立的下载来源表，不修改原下载身份、版本或去重键。历史记录在实际补扫到云盘日期目录时补齐；缺少依据显示“日期未知”，纯本地文件显示“本地”，多个已知来源日期显示“多日期”。已记录文件大小和修改时间的来源不会套用到后来替换的本地文件。

非文件名列按表头字体及显示内容自动分配宽度；文件名占剩余空间，悬停显示完整名称。已验证1366×768下四个平台表头及日期列完整显示。
