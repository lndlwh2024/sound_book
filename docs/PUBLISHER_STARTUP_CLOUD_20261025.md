# 启动、会话与云盘监听修复（2026.10.25.1）

## 本次证据及其边界

只读取最新诊断包的任务日志、摘要和最后页面，不使用旧任务补齐新任务结论。

- `书声最新任务诊断包(1).zip`：任务及导出器为 2026.10.23.3；视频号实际打开了登录页，保存了DOM和截图，报 AUTH_REQUIRED。该包没有云盘请求记录，不能从中还原10月25日漏下载的具体请求。
- `书声最新任务诊断包11.zip`：任务及导出器均为 2026.10.24.1。09:33:12开始检查抖音，09:33:23报 `BrowserType.launch_persistent_context: Timeout 10000ms exceeded`，已创建Chrome进程但没有返回可用的浏览器上下文；尚未检查抖音是否登录。本次没有截图，原因是启动接口超时，不能用这个结论解释之前已经采到视频号二维码的任务。
- 使用两个已冻结的23.3/24.1 EXE及隔离用户目录，复现了旧版仍运行时点击新版，新版退出、旧版继续服务。它能解释版本不一致的可能路径，不能解释退出旧版后24.1本身的抖音启动超时。

## 改动

1. 保留浏览器默认启动空白页，不再因存在 `Session_*` 就移除它。会话文件存在并不保证历史窗口可恢复；即使没有可恢复标签，也要有初始页面供Playwright完成启动。恢复后按标签历史长度和地址选择原标签，避免误用新增标签的sessionStorage；完成空白页加载后再做媒体检查。仍使用原账号目录及原生会话恢复，不复制或导出凭据。
2. 登录、预检和上传的浏览器启动等待统一为30秒；上下文初始化失败时关闭新建上下文，避免账号目录被残留浏览器占用。预检明确区分启动超时、页面检查异常和实际需要登录，日志保留阶段及底层异常。启动超时不改写为账号登录失效。
3. 用户明确启动连续部署后，云盘监听独立于平台发布预检。某个平台需要扫码时，已授权云盘仍可下载到本地队列，发布仍须预检通过；单文件手工部署保持本地范围。云盘总开关、暂停和停止继续生效，所有绑定使用公共轮询间隔。
4. 调度键包含北京时间日期，跨日后立即检查新日期，不沿用前一日最长24小时的等待期限。同日轮询间隔及失败退避保留；已完成的云端版本不会重复下载，归档仍需全部必需平台完成。
5. 界面区分“监听暂停/未运行”和实际检查结果；旧日期标为“上次检查”，不再显示为今天。常规等待本地文件日志固定INFO，文字提到“失败2”不会将等待提示误判成错误。
6. 跨版本或跨路径重复启动时显示正在运行位置与本次尝试位置，明确告知新版未启动；同版本同路径仍正常唤醒原窗口。旧版没有元数据时明确标为未知，不能假装确认了旧版身份。
7. 诊断包继续仅导出最新任务日志及每组最后两次页面证据，另附当前程序版本、PID、入口及必要的公共云盘状态快照，明确标为运行时上下文。云盘快照包含最近两次扫描的日期、条目数量、媒体就绪条件和错误，便于区分未监听、未找到日期目录、权限/文件未就绪和下载失败；不打包历史任务日志或凭据。

## 验证与交付

本地使用临时账号目录、Chrome 141和拦截页面验证五个平台“登录→关闭→预检→关闭→上传入口”保留会话Cookie、sessionStorage及localStorage，真实登录页仍阻止发布。使用模拟Drive验证跨日发现两个文件、预检失败仍下载、公共间隔、暂停、去重和归档。

18组针对性测试共356项通过，详细结果保存在 `output/publisher-20261025-test-results.json`。Qt界面测试按模块隔离进程运行，避免多次销毁/重建QApplication干扰验证。

这些测试验证程序行为；未复现X230上完整的10秒启动超时环境，也未取得这次视频号平台端会话失效的全部原因。启动页恢复与较长等待分别修复已发现的脆弱条件，不能宣称这次每次掉登录均已定位为同一原因。

两种界面共用相同发布代码与版本；本次另生成部署版EXE及ZIP。没有更改VPN/PAC代理分流。新版解压到独立目录，从旧程序托盘菜单退出后运行；若使用登录自启，应在新版运行设置重新保存以更新EXE路径。
