# 生产控制与监控确认方案

- 确认日期：2026-10-16（北京时间）。
- 状态：**工作区源码已实现并通过自动化回归，尚未打包发布**。真实长书和GPU高温压力任务仍需实机验收。
- 范围：自然章节可选最大时长、定时安全暂停、分镜级GPU温控、两行监控。
- 冲突规则：在上述范围内以本文最终确认规则为准，不替换其他既有需求，不将历史修复记录改写为本次实施结果。

## 1. 管线保护原则

1. 保留现有解析、清洗、正文校验、TTS、CPU意象预提炼及汇合、真实时间轴绑定、插画、超分、字幕、混音、视频合成和质检的依赖关系。新增边界检查不意味着重排这些步骤。
2. 保留完整自然句、真实音频时长、原文字幕和现有音频质量检查，不硬切发音、不伪造静音、不省略正文。
3. 保留现有GPU资源互斥、工作进程释放、增量缓存与断点续跑机制；不扩大GPU并发，不中断正在写入的音频或成品。
4. 两个定时开关及自然章节限长默认关闭，旧配置缺少新增字段时同样按关闭处理。关闭时不改变原有分集和生产结果。
5. 本次生产控制不改动多平台发布、去重、上传额度、账号、DOM或归档逻辑；同时运行的上传任务不被生产计时暂停。

## 2. 自然章节的可选最大时长

### 2.1 界面和启用条件

```text
分集模式：[按自然章节 ▼]  ☐ 分集最大时长 [60 ↕] 分钟
```

- 复选框默认不勾选；数值默认60分钟，未勾选时数值及关联单位置灰不可配置。
- 仅在自然章节模式显示、启用。切到固定时长模式时该规则不参与分集，不改变固定时长逻辑。
- 未启用时仍按自然章节一章一集；启用后允许同一长章节生成多集，不跨章节合并。
- 最大时长必须为正值；具体控件上下限应在实施时一致校验，不能让零或负数进入规划器。

### 2.2 实际切分规则

1. 计划预览使用字数及语速估算，标注“预估”；最终边界使用完整TTS文件的真实物理时长，并计入已有片头、片尾等实际占用的时间。
2. 对当前待输出段，以最大时长为截止点，在截止点前5分钟内，选取最靠近截止点且不超过截止点的完整分句结束位置。
3. 如上限60分钟，则优先选55～60分钟内最后一个合法结束位置。时长等于上限不拆；短于上限不拆。
4. 剩余内容仍超长时重复上述过程，可拆为三集或更多，不限于两集。各段正文按顺序连续、无重复、无遗漏。
5. 上限不足5分钟时，搜索窗口从当前段起点开始。窗口内无边界时向前找最近的完整分句边界；若首个完整分句已超预算，明确提示不能满足上限，不机械截断声音、不输出假合格成品。
6. “分句结束位置”必须有可靠的音频边界。现有原子SpeechUnit包含多个自然句且无可靠内部时间戳时，不按字符比例猜切点；应选已知合法边界，或在保持完整句子的前提下补齐可验证的时间映射。
7. 所有字幕、分镜和音频区间按实际边界重组，输出段时间轴从0开始；连续内容的首尾覆盖必须通过校验。

### 2.3 分镜跨集

- **跨集分镜在上下两集各呈现一次**，分别生成该集内的画面呈现记录；沿用同一已生成图片/意象，不重复绘图。
- 旁白及字幕按分句边界分配，不因同一画面出现两次而重复朗读或重复字幕。
- 示例：一个分镜6句话，在第2句话后分集；上集显示该分镜并朗读1～2句，下集再次显示该分镜并朗读3～6句。
- 各集中的画面引用仅占据对应音频区间，不能通过重复完整分镜音频把视频再次推过最大时长。
- 两段使用“章节名·上/下”；三段及以上使用“章节名·第N段”，内部保留稳定的原章节和原语音单元引用。

### 2.4 缓存和历史兼容

章节语音生成与最终分集拆开：已经校验的语音切片可复用，重新分集只重组时间线。复用必须检查正文内容、章节/语音单元标识、音色和合成参数，不能只看`ep_XX_units/unit_XXXX.wav`存在。启用/关闭限长或修改上限后，失效的是分段计划及其派生产物，不应无条件重做所有TTS或误用旧集序号的声音。

原产物不静默覆盖；新分段映射与已完成记录应原子保存，暂停和恢复不得丢失原分句或跨集画面关联。

## 3. 同一行的两个定时条件

原左侧GPU温控位置改为同一行：

```text
☐ 执行时长 [分钟 ↕] 分钟后暂停    ☐ 执行到 [HH:mm ↕] 北京时间暂停
```

- 两项默认均不勾选，对应参数置灰；均由用户调整。仅配置小时、分钟，不增加日期输入。
- 两项可独立启用，也可同时启用；任一满足即登记一次暂停请求，不能互相覆盖。
- 执行时长：从点击“开始生产/继续生产”开始本轮计时，排除手动暂停、温控冷却时间。只生成生产计划不计入。持续时间计算使用单调计时，避免系统校时干扰。
- 时间点：显式按北京时间计算下一次到达的时刻；今天已过则取明天。界面展示最终目标日期/时刻，例如“明日01:00”，消除跨日歧义。因休眠等原因错过目标，恢复检查时登记到期请求，不能悄悄顺延一天。
- 点击“继续生产”时，执行时长重新开始一轮；时间点重新计算下一次到达时刻。已经触发的旧请求在用户继续时明确消费，不能刚恢复就重复暂停。
- 配置保存，启动时恢复；运行中的任务使用一致的任务配置与计时状态，不能因重建工作线程重复装载旧到期请求。重启恢复不得自动执行已暂停的任务。

## 4. 统一的分镜级安全暂停

### 4.1 安全边界

- 手动、时长、指定时间点、GPU温控共用控制入口，保留各自原因；到期/超温首先提出请求。
- 分镜模式：完成当前整个分镜所有TTS切片、质量检查和断点持久化后停，不仅完成当前一句，也不启动下一分镜。
- 若分镜跨越两个输出集，其各集内的画面呈现记录与语音分配必须一致；控制层记录当前安全工作单元及其完整范围，不能误把下一集的正文重复合成。
- 非分镜模式：完成当前完整语音单元后停。缓存全命中路径也要检查控制状态，不能绕过暂停请求。
- 解析、绘图、超分、混音、视频合成等阶段在完整且可恢复的工作单元结束后检查请求；界面说明正在等待哪个步骤，不强杀正在写文件的进程。
- 保存断点后直接发送PAUSED并结束相应生产执行路径，不能继续触发“本集切片缺失”的失败校验或把正常暂停标成ERROR。

### 4.2 按钮互斥

| 状态 | 开始生产 | 安全暂停 | 继续生产 |
| --- | --- | --- | --- |
| 正在生产 | 禁用 | 可用 | 禁用 |
| 等待完成当前分镜 | 禁用 | 禁用，显示暂停中 | 禁用 |
| GPU温控冷却 | 禁用 | 可请求转为用户暂停 | 禁用 |
| 已安全暂停 | 禁用 | 禁用 | 可用 |
| 完成/失败 | 按既有就绪和断点规则恢复 | 禁用 | 按既有断点规则处理 |

状态文本、四个生产按钮、计时器和实际后台状态必须统一；生产线程未结束不能因收到中间状态再次启动生产。

## 5. GPU温控简化后的行为

### 5.1 配置

温控整体移到底部独立边框：`☐ GPU温控 上限[75]° 复工[60]° 冷却[1]分`。沿用现有启用默认和参数范围，未勾选时三个参数置灰；“开启”重复文字删除。复工温度必须低于上限。无论是否启用温控，温度监测仍可显示。

### 5.2 触发和复工

1. 温度达到上限时登记温控请求，在当前完整分镜TTS完成后进入冷却；不再使用旧的单句冷却/分镜剩余TTS补做设计。
2. 上限是申请冷却的触发阈值，不保证等待分镜结束期间温度不继续升高；用户已接受该安全边界导致的延迟。
3. 仅温控触发：同时满足“达到最低冷却时长”和“有效的新鲜温度不高于复工温度”后，自动继续下一工作单元，直至完成或再次触发温控。
4. 冷却中收到定时/手动请求：当前分镜已经完整，保存状态并转为PAUSED，无需再补做当前分镜；温控原因解除不能自动清除定时/手动原因。
5. 同时存在温控和定时/手动请求：用户点击继续，且温控条件满足后才恢复。冷却起点需保存，不能因状态变更提前跳过冷却或反复重置已完成的冷却时间。
6. 温度查询失败、数据过期或设备不匹配显示“未知/不可读”，不能按0℃判断已降温；有效温度恢复前不自动复工。

## 6. 最终确认的监控UI

```text
第一行：CPU｜CPU功耗｜内存｜GPU｜GPU频率｜GPU功耗｜GPU温度｜显存｜显存频率｜显存接口
第二行：磁盘读写及活动率｜GPU温控配置框｜进度条｜用时
```

- **GPU利用率现有名称与采集逻辑完全保持，不改名，不改成CUDA专用指标，不拆分引擎展示。**
- 删除“📊 硬件负载：”字面标题。CPU、内存、GPU温度及显存保持原有指标含义，新增GPU瞬时功耗常态显示。
- 磁盘常态显示当前输出目录所在物理磁盘的读速率、写速率和活动率，标识所属输出盘；活动率不是空间占用率，不把其他磁盘混成该盘负载。
- 两行等高，至少48像素；温控数值框加宽至104像素，进度条占剩余宽度。磁盘读写分别标注MB/s，用时位于最右端。
- 增加应用启动默认纵向高度，为两行监控提供完整空间；受屏幕可用区域约束，不把窗口撑到任务栏之外。指标均衡分配，控件完整、列对齐，不靠缩小文字或裁切换取空间。
- 进度条使用剩余弹性宽度，用时保留稳定宽度；不新增配置区滚动条来掩盖底栏空间不足。

### 6.1 常态展示与移除项（最新布局修订）

GPU核心频率、显存频率、显存接口利用率移到首行常态显示。移除监控详情按钮及浮层，GPU性能状态不再展示。显存接口利用率不是显存容量占用比例。不可用值显示`--`，不显示伪造零值；原独立CUDA活跃/进程数不列入底栏。

### 6.2 采样与温控共享

外部显卡查询、磁盘性能采样放在后台，主线程只接收结果更新UI。温控与显示读取同一份带采样时刻、GPU设备标识和有效性的快照，按实际生产设备控制；故障及恢复日志去重，避免刷屏。保留GPU利用率原查询字段与语义。

## 7. 只读监控调研结论

以下为2026-10-16本机审计结果，不是固定默认值，也不据此自动修改温控阈值。

| 项目 | 本机取得情况 | 本轮决定 |
| --- | --- | --- |
| GPU核心温度、GPU利用率、显存、CPU负载、系统内存 | 已能读取，原有监控已使用主要字段 | 常态保留 |
| GPU瞬时功耗 | 可读，采样约3.9W | 常态新增 |
| GPU核心/显存频率、显存接口利用率 | 可读 | 首行常态展示 |
| GPU性能状态 | 可读 | 最新布局不展示 |
| 输出磁盘读写速率及活动指标 | 可读，能区分输出盘和系统盘 | 常态新增 |
| ACPI热区THM0 | 可读，采样约79℃；无法可靠对应CPU核心位置 | 不加入本轮默认展示或控制 |
| CPU封装/各核心温度 | 当前未取得可靠值 | 不展示，不承诺无需额外组件即可读取 |
| GPU显存温度、风扇转速 | 当前驱动返回N/A | 不展示 |
| SSD温度 | 当前存储接口读取失败 | 不展示 |

ACPI热区由固件定义，可能反映多个部件共同影响的区域温度，不能把THM0直接标成CPU温度。调研未安装传感器工具、未改变硬件设置。

参考：[NVIDIA监控字段](https://docs.nvidia.com/deploy/nvidia-smi/)、[微软热区与性能计数器说明](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/examples--requirements-and-diagnostics)、[LibreHardwareMonitor官方项目](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor)。

## 9. 实现与验证记录（2026-10-16）

### 9.1 工作区实现

- 新增`src/core/production_control.py`，隔离生产时长、北京时间点、暂停原因及冷却计时。
- 新增`src/core/episode_segments.py`，按完整语音单元真实时长分集、复制跨集画面引用并校验语音缓存指纹。
- `src/app/task_bridge.py`接入完整分镜安全边界、原子断点、定时暂停与温控恢复；保留现有生产步骤的先后依赖，调用原字幕、音频QC、混音和视频合成实现。修正分镜绑定到展开字幕行而非原始语音单元索引的错位风险。
- TTS缓存按正文、音色、参考音频/文本及合成配置隔离；分集上限不参与语音指纹，修改上限仍可复用声音。旧无指纹语音目录保留，但无法验证的旧切片不会直接混入新缓存，首次使用可能重新合成。
- 已完成限长分段需重新校验音频、时长、字幕和预期视频后才能跳过；片段命名包含章节与分段，限长和渲染配置隔离，避免更改配置后覆盖旧分段。
- `src/utils/resource_sampler.py`后台共享采样现有GPU综合利用率字段及功耗、频率、性能状态、显存接口利用率；使用Windows原生计数器读取CPU、内存和输出磁盘数据，无新增运行依赖。
- `src/app/resource_monitor.py`和主窗口实现最终两行顺序，频率及显存接口常态显示，移除详情入口；未启用控件置灰，生产中冻结配置，设置通过QSettings保存。
- 插画管理器只增加可选的安全检查点回调，默认调用行为不变；新功能不改动发布、账号、去重或上传调度代码。
