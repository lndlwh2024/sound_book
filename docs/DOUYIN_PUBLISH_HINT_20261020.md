# 抖音发布说明误判修复与任务间隔说明

统一版本：2026.10.20.5。完整版和独立部署版使用同一份抖音发布实现。

## 本次修复

现场诊断包中的抖音页面包含以下常驻说明：

> 点击发布后，如作品还在上传中，请勿关闭页面，等待上传发布完成。

旧代码因其中含“上传中”，把这条说明当作实时上传状态。实际进度条已消失、当前视频预览和“重新上传”入口均已就绪，程序仍留在上传等待阶段，直到原有30分钟上限才失败，尚未执行发布按钮检查和点击。

本次仅从抖音待完成状态文字中排除这条完整说明，兼容排版空白及中英文逗号。说明本身保留在页面上；不会关闭提示、点击发布或修改页面内容。真实上传、转码、处理和失败提示仍使用原有判断。

排除说明不等于上传成功。既有完成校验继续要求真实完成证据，或本次已观测到上传活动、进度消失、表单/视频预览/重新上传入口就绪且连续2秒稳定。最终发布成功仍需核验本次平台回执。

本次保持现有异常退出、上传总上限、控件超时、停止操作、两次尝试上限、30秒任务间隔及5分钟目录轮询不变。不实施此前排查报告中的分层超时、无进展提前退出、调度间隔或浏览器视口调整；生产、归档和去重逻辑不变。

## 为什么两个任务之间看起来很慢

书声一次只执行一个浏览器发布任务。同一文件按所选平台依次发布，其他平台处理完成后再执行允许的失败重试。

现场日志中，两次抖音尝试之间约4分钟，实际安排如下（北京时间2026-10-20）：

| 时间 | 书声在做什么 |
| --- | --- |
| 08:52:05 | 抖音第一次失败 |
| 08:52:06—08:53:34 | 快手实际发布，88秒，成功 |
| 08:53:34—08:54:04 | 固定等待30秒 |
| 08:54:04—08:55:42 | YouTube实际发布，98秒，成功 |
| 08:55:42—08:56:12 | 固定等待30秒 |
| 08:56:12 | 回头重试抖音 |

这段时间包含3分06秒的实际发布、1分钟固定等待及约1秒任务切换。两次抖音各自因说明误判而耗尽30分钟，才是本次长时间拖延的主要原因。

另外，一批任务结束后默认每5分钟检查目录；这不是每个视频之间都要等5分钟。当前有新文件在上一批执行期间到达时，也可能在批末继续等待轮询。本次不调整此调度行为。上述固定间隔和抖音文案误判是两个不同问题。

## 验证范围

使用本地HTML复现现场说明与真实进度、转码、失败状态，不操作线上账号或实际发稿。回归覆盖：说明不产生虚假的上传活动；真实进度不足时不提前放行；进度消失后说明仍在页面可按原完成规则继续；没有本次上传证据、缺少预览、正在转码及上传失败时仍被阻止；发布成功回执、停止和原有等待流程保持。

部署包另外核验源码摘要、冻结代码、ZIP完整性及独立运行自检。目标X230的真实发布仍需现场验证。
