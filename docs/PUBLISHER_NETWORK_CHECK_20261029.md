# X230 PAC / Google 网络诊断工具

这是独立的只读诊断工具，不是新版书声，不用替换现有发布程序。

## 在 X230 上操作

1. 保持当前 PAC 模式和已登录的视频号；不必停止书声或退出 Google 云盘客户端。
2. 将诊断工具压缩包解压到可写文件夹，例如桌面或下载目录。
3. 双击 `ShuShengNetworkCheck.exe`。不需要安装 Python 或用管理员权限运行。
4. 等待窗口显示“完成”，通常约1—2分钟。窗口会显示各项进度；遇到网络阻塞会超时结束该项。
5. 把工具旁自动生成的 **`ShuSheng-Network-日期时间.zip`** 发回。该ZIP里有中文说明和JSON明细。按回车退出窗口。

不需要重复扫码、切换全局/PAC或发布任何测试视频。P1 Gen3的对照报告可以后续再取，先取得X230故障现场。

## 自动检查内容

- 当前用户实际PAC地址是否存在，PAC服务是否可访问，脚本大小及SHA256摘要；不保存PAC正文。
- 当前进程环境代理、系统静态代理、绕过规则是否影响书声实际路径。
- Google令牌服务 `oauth2.googleapis.com`、目录与媒体API `www.googleapis.com` 的路径选择。
- DNS解析、本机已配置HTTP代理端口连通性。
- 对照当前路径、强制直连、配置中已有的本机HTTP代理，分别尝试不带账号的HTTPS请求。

所有探测均无Google/微信账号令牌、Cookie和代理密码；不会读取书声账号文件、订阅地址或VPN节点配置。不会更改注册表、代理、DNS和VPN模式，不启动浏览器，不下载或上传用户文件。只写入本工具的报告。

报告包含必要的网络端点、Google域名DNS结果、Windows版本、HTTP状态和错误码，不包含Windows用户名或计算机名。带账号密码的代理不会被用于主动探测；只标记“存在凭据”。

## 结果边界

- HTTP401/403/404/405可能是无账号探测的正常响应，说明已收到服务器HTTP响应，不能据此判断账号失效。
- 基础HTTPS可达不等于真实Google文件下载已验证；报告用于定位PAC、代理及网络层差异。
- 当前只自动比较系统配置中能读到的本机HTTP代理，最多3个，不扫描其他端口，不把SOCKS端口误用为HTTP端口。
- 此工具不访问视频号，不会单凭网络结果认定微信业务码300333的原因。
- 构建环境为Windows11、Python3.12.11 x64；包含本地Windows PAC引擎测试及成品自检。X230 Windows10实网仍需目标机器运行本工具，未宣称已验证或修复。
