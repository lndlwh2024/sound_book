## 已确认的代码缺陷与修复

1. **预检与上传之间的浏览器会话丢失。** 共用工厂原来反复关闭并重新打开持久化目录，却没有启用原生会话恢复。同版本Chrome 141的本地实验复现：长期Cookie和localStorage保留，会话Cookie与sessionStorage丢失。独立账号目录并不等于所有会话数据都能跨关窗保存。

   现在登录、预检、上传统一使用Chrome原生会话恢复，并去掉Playwright额外创建的启动空白标签，续用原标签的sessionStorage；否则会出现Cookie恢复而sessionStorage仍丢失的情况。关闭前把页面停在空白页，下次不恢复旧投稿文档；清理多余启动标签，避免越开越多。YouTube正常Chrome/Edge专用目录也使用相同策略，继续保持原浏览器、原账号目录与频道ID校验。没有把Cookie改为永久、复制到别的账号或导出凭据。

   本地实验能证明程序关闭会话造成的数据丢失；这两个诊断包没有Cookie寿命和平台失效原因，不能据此认定本次所有掉登录都只有这一个原因。平台端到期、撤销和安全验证仍须按实时页面处理。已经丢失或被平台撤销的会话需要重新登录，新版不伪造登录成功。

2. **页面跳转导致通用错误。** 共用等待循环原来只包住条件读取，未包住前面的页面拒绝检查；该检查的 `page.evaluate` 在跳转时抛错就直接退出。现在仅对明确的文档跳转/框架切换异常，在原有期限内重新检查新文档；实际进入登录页就明确报告“当前浏览器需要登录”，保留DOM和截图。真实关闭页面、脚本错误、验证或网络问题不会一概算成登录失效。已保存的发布成功回执继续有效。

3. **云盘日志错误归入账号平台。** `DriveWatchWorker.emit_log` 和界面状态回调原来按绑定账号的平台记录云盘事件，导致视频号标签被每轮云盘刷新覆盖。现在事件标记为公共云盘，另存绑定平台供定位，旧日志回放也按阶段分流。只有“全部”和“公共/云盘”显示这类记录；阅读旧日志时保留滚动位置。

4. **扫描抹掉未登录状态。** `fresh_result()` 原来把未封顶的非成功状态统一改成 `PENDING`。手工重试前会扫描整个目录，因此其他文件也被错误改成“待上传”。现在保留需要登录、账号受限、验证、配置错误及既有失败原因，实际处理对应文件时才进入上传状态；成功记录不重置。旧版仅写在报告、没有进入账本的账号阻塞会补齐，明确的手动重试和较新账本不会被覆盖。

5. **失败说明与采集说明混淆。** 后续文件沿用账号阻塞时，现在单独说明“本文件因账号需要登录暂停，尚未上传文件；沿用本轮账号检查结果”，标明来源文件，并保存每个文件的真实阻塞原因。真实打开浏览器的失败会保存当时页面。缺证据时只写“本次没有保存截图或DOM”，不再据此断言浏览器没开。失败归档日志首先给出中文结果与实际原因，再给证据位置和采集问题。

失败DOM新增浏览器启动时、采集时的会话数据计数，用于继续区分重开丢失与平台要求重新认证；只保存数量，不含Cookie名称、值或会话令牌。预检只证明检查当时可访问，实际上传前仍重新校验。

## 验证与范围

使用临时账号目录和拦截的本地模拟页面验证五个平台“登录→关闭→预检→关闭→上传入口”的连续会话保留、真实登录页仍被拒绝、跳转异常重试、单文件手工部署不改写其他文件、历史阻塞修复及日志分流；不使用真实账号或真实投稿。

共享代码同步适用于完整版与部署版；部署包另做冻结程序自检。没有更改VPN、PAC或代理路由。尚不能代替Win10 X230的真实平台验收。
