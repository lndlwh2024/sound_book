# 分集上限、中文成片读取与输出命名 · 2026.10.20.4

## 上限含义

“分集最大时长”是上限：自然章节的真实TTS时长短于或等于上限时，保留一集；超过时，继续沿用现有完整语音单元边界拆为多集。没有最低时长要求，不补时长、不机械截断声音、不省略原文。

现场第38集视频实际时长3448.274秒（57分28.274秒），低于59分钟上限。此次失败是读取媒体信息异常，而不是成片不够长。

## 编码根因与修复

普通Windows启动时，Python默认使用CP936/GBK；FFprobe的JSON是UTF-8，中文路径/元数据可使子进程读取线程解码失败，最终得到空stdout。旧代码将这类读取失败和真实超长一起报为“未满足分集最大时长”。

现在FFprobe的JSON按字节读取解析，最长等待30秒，不依赖系统文字编码。生产中的FFmpeg文本日志明确按UTF-8读取，修复音频质检、混音、视频合成和预览的同类问题。WAV头部的快速读取路径保留。

最终检查分别处理：读取不到有效正时长时提示“成片时长读取失败”；真实超长时显示实际秒数与上限；短于或等于上限时正常完成。继续保留现有0.1秒封装容差。读取失败和超长均保留文件，不冒充完成。

## 输出视频命名

- 无需拆分：完整沿用原命名，例如`巴菲特致股东的信_第38集_57m_[提交号].mp4`；原小人书模式保留原有`_P_`标记。
- 实际拆分：仅使用`巴菲特致股东的信_第38集-N_[提交号].MP4`，N从1开始；无论标准封面还是小人书，均不额外添加章节名、时长、限长参数、_P_或其他标记。
- 内部断点、分段ID和渲染工作目录继续记录合成及渲染参数，用于可靠复用；这些内容不再写入输出视频文件名。
- 已有业务资产保持原样；本次不批量改名，不修改原始电子书和TTS切片。

## 验证

在关闭Python UTF-8模式的Windows默认CP936环境下复现并修复现场文件读取；覆盖中文路径MP4与WAV质检、短于/等于/超过上限、无效时长、不拆分命名保持、二段/三段的标准封面和小人书命名、暂停与恢复、缓存复用、字幕和混音，以及真实短视频合成。通过将子进程读取线程异常作为测试错误，避免编码错误被“测试通过但有警告”掩盖。
