# YouTube手工登录交接修复：2026.10.19.1

用户反馈：Win10中正常Chrome已登录，但书声所有验证控件禁用；关闭书声登录会话后仍未登录。截图日志表明程序停留在等待手工浏览器退出，没有恢复实际频道验证。

## 已确认的代码问题

上一版只轮询Popen启动进程是否退出，未提供手工登录完成操作；手工状态把账号核验按钮一起禁用。“关闭会话”则设置整个工作线程的关闭标志，绕过后续频道读取和保存。浏览器仍开着、留有后台进程或启动进程与实际实例生命周期不一致时，都无法靠该判断完成交接。远程目标机当时究竟是哪种进程状态，尚无本机日志，不能断言。

## 修复行为

1. 手工状态底部按钮变为可用的“登录完成，验证频道”。点击后仅向拥有此账号专用目录、且可执行文件与配置匹配的Chrome/Edge可见窗口发送WM_CLOSE正常关闭请求，不强杀进程，不关闭用户日常浏览器或其他profile。
2. 按Chromium的专用profile消息窗口及lockfile检查目录占用，连续确认释放后才重开同一目录，避免把后台进程寿命当成登录窗口寿命。20秒未释放会给出明确重试指引，验证按钮保持可用；关闭/取消等待及时结束，不无限阻止退出。
3. 如果关闭书声时专用浏览器仍开着，下次进入原账号登录窗口会恢复该次交接，不再重复启动或覆盖目录。
4. 完成交接后自动读取实际YouTube频道ID和昵称并通过原账号配置保存；缺少有效UC频道ID或与绑定频道不符时不标记AUTHORIZED。普通YouTube“核验登录账号/频道”也执行实际读取，不把用户点击视为自动核验成功。
5. 暂停采集与昵称按钮呈灰色；当前操作和下一步在登录会话日志中说明。抖音、快手的原账号登录目录保持不变；两版共用这套代码，完整版安装包未重新生成。

## 使用方式

退出旧书声，解压整个新版到新目录，保留LOCALAPPDATA/ShuShengPublisher。进入原YouTube账号的登录窗口：若正常浏览器已关闭，会复用已保存登录并读取频道；若仍开着，则恢复交接。需要时点击“手工登录Google”，本人登录并选对频道后点击书声底部“登录完成，验证频道”，等待主界面显示实际频道昵称和已登录。

“取消等待并关闭”仅退出等待，不伪装登录成功；已保存数据保留。更新到新安装目录时，如已开启登录自启，应在新版运行设置重新保存路径。无需重建账号、清理profile、重新登录抖音/快手或重新采集所有平台DOM。

## 验证与限制

增加手工验证按钮、及时取消、交接超时、恢复遗留浏览器、进程仍活着但目录已释放、实际频道持久保存等回归。用正常启动的Chrome/Edge打开本地临时HTML并写入合成测试会话，验证正常关闭、目录释放、重开后的会话保留，同时保证另一个独立浏览器仍可使用；不访问Google登录或真实投稿，不读取用户Cookie。

Windows11开发机的上述验证不能代替X230的真实Google会话与频道验收。新版保留目标机待验收标记，发行摘要和冷启动证据位于artifacts/youtube-handoff-20261019。

实现依据：[Chromium profile消息窗口及锁](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/process_singleton_win.cc)、[Windows WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close)。
