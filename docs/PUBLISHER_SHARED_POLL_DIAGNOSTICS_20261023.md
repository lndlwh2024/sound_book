# 公共轮询与最新任务诊断（2026.10.23.3）

## 公共云盘轮询

“公共配置-跨平台云盘绑定”的第二行依次为启用开关、更换连接、轮询秒数、留白、连接/断开。控件高度统一，无新增表单滚动条。各平台账号的目录配置不再显示轮询间隔，独立保留监听开关、云盘目录、本地目录及立即检查。

公共间隔立即保存至 `multi_platform/accounts.json` 的 `cloud_poll_seconds`，同步所有平台界面与后台调度，默认15秒，范围5至86400秒。旧配置没有公共值时使用15秒；历史账号内的 `poll_seconds` 仅兼容读取，不参与调度。保存失败恢复原值并记录原因。关闭云盘接入保留间隔、授权和账号目录，本地发布继续。

各账号仍独立维护检查进度和失败退避。失败退避不会短于公共间隔；立即检查保留原有独立触发行为。此间隔只控制云盘刷新，不改变本地扫描及上传衔接等待。

## 最新任务诊断

部署预检、配置检查失败和正式发布均登记任务ID；预检与随后的发布沿用同一ID。任务开始、结束时间、版本及独立日志保存于 `.diagnostics/<任务ID>/`，最新任务指针保存在 `.diagnostics/latest-task.json`。旧任务较晚结束不会覆盖新任务指针；任务日志不受正常日志轮转影响。

导出规则：

1. 有正在运行的预检或发布任务时，导出该任务当时的快照；否则按最新任务指针导出最近启动的任务。
2. 仅导出该ID的结构化日志（`task-events.jsonl`），事件按ID去重；不重复放入每个失败操作的整份任务日志。
3. 仅选该任务的失败证据，包括尚未归档的当前页面；同一平台、账号、文件、失败阶段最多保留最后两次截图与DOM。不同文件、账号和失败阶段分别保留。
4. `task-summary.json` 保存任务时间、版本、状态和对应发布报告的紧凑结果；省略报告中的重复过程日志。`diagnostic-manifest.json` 记录选中的任务ID、快照时间、文件摘要、保留策略、采集错误和缺失归档。
5. 最新任务成功时不带入旧失败截图；缺日志、缺截图或缺DOM时明确记录，不用旧任务证据补齐。没有任务时提示先执行检查或发布。

旧版本没有任务索引时，仅从保留的结构化日志推断最近启动的任务，并在清单中明确提示推断及轮转限制。索引损坏时报告错误，不退回导出所有历史任务。本地已有历史证据不删除。

本次按要求暂缓网络问题：没有调整VPN、PAC、浏览器代理、导航或视频号分流逻辑。

验证使用本地模拟页面、离线任务及1366×768界面检查；不等同于Win10 X230的真实平台发布验收。
