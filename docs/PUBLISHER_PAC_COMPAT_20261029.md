# 2026.10.29.2：Google云盘强制代理及混合PAC兼容修复

## Google云盘必须代理

2026.10.29.1只修复PAC传输兼容，仍尊重PAC对Google返回的DIRECT。根据用户进一步明确的要求，2026.10.29.2对书声的Google令牌、目录/API及文件下载请求强制使用配置中的HTTP/HTTPS代理。PAC明确DIRECT、没有代理、代理配置无效时在发送请求前停止并报错，不改为直连。选中的代理不可达时保持失败，不回落直连；NO_PROXY及系统绕过列表不能覆盖这条Google策略。

此拦截只针对本客户端固定使用的oauth2.googleapis.com和www.googleapis.com，不代表对系统内所有Google应用实施网络策略。国内平台浏览器直连规则保留在其PAC中，YouTube浏览器继续使用用户设定的代理规则。程序没有硬编码58591或其他代理端口，也没有修改Trojan配置。

## 触发条件与修复

Trojan-Qt5 的公开 GFWList 模板会返回如下代理列表：

`SOCKS5 127.0.0.1:51837; SOCKS 127.0.0.1:51837; PROXY 127.0.0.1:58591`

旧代码直接用 WinHTTP 解析该列表。在构建机的真实 Windows 引擎上，旧路径对这条结果返回 NO_PROXY，书声随后直连 Google 并超时。旧诊断工具因此也把结果显示为 PAC_DIRECT。这不足以证明 PAC 规则本身要求直连。

PAC兼容层先执行原 PAC 的站点匹配，再移除本 HTTP 客户端不能使用的 SOCKS 传输项，保留原来的 HTTP 代理及明确 DIRECT 顺序。随后Google云盘客户端单独执行强制代理检查，DIRECT会在发送请求前被拒绝。国内浏览器仍遵循用户的直连规则。程序不硬编码实际代理端口。

兼容脚本通过一次解析期间的随机路径本机 HTTP 端口交给 Windows 引擎。解析结束后监听线程和端口关闭；成功、失败及并发分支均有测试。不更改系统代理、PAC文件或Trojan设置，不安装服务。

## 云盘错误说明

网络失败现在注明 Google 令牌请求、目录/API 请求或文件下载，并给出实际选中的 PAC代理、系统/环境代理或直连路径。不会输出代理密码、Google令牌、PAC地址查询参数或文件ID。

日志中的 `youtube:账号ID` 可以表示该账号绑定的共享Google云盘扫描，不能仅据此前缀判断YouTube上传故障。此次用户截图报的是Google云盘超时，YouTube账号仍显示核验通过。

## 验证与交付边界

- 使用真实Windows PAC引擎、本机模拟PAC服务，验证SOCKS5/SOCKS/HTTP混合列表、明确直连、仅SOCKS、语法错误、源读取失败及并发解析。
- 在原作者保留的GFWList模板中填入本次完整用户规则：带`^`的规则能正确匹配。原混合列表被旧WinHTTP路径判为直连；只改成HTTP列表后，Google/YouTube为代理，三个国内平台为直连。规则文本格式不是该复现中的原因。
- 发布EXE的离线自检包含上述混合代理解析和国内直连检查；只访问本机临时PAC服务，不读取账号或访问真实平台。
- 独立网络诊断工具升级为2026.10.29.2，使用相同兼容解析并标记适配版本。旧2026.10.29.1诊断工具的PAC_DIRECT结果存在上述歧义，应结合新版或原始PAC核实。
- 最终GUI联测发现一次替换启动时旧实例元数据未更新，隔离目录留下新临时文件和旧nonce；单独重试通过。对Windows短暂文件共享占用补上最多150毫秒的元数据写入重试，并加入占用故障注入测试，降低误留旧nonce导致正常退出请求被拒的风险。
- YouTube上传流程、微信认证材料及账号目录没有修改。微信此前300333的确切触发原因仍未查明；也未据此认定Google官方客户端一定具有相同缺陷。
- Windows10 X230真实目录扫描、文件下载及长时间会话仍需目标机器验证；不能用构建机本地测试替代。

## 使用

退出旧书声后，从新目录运行2026.10.29.2版。Trojan保持当前PAC模式和现有用户规则，不再为此次修复改写规则或切换全局。点击“立即轮询”，确认目录检查完成；有未下载文件时再确认真实下载。

单独发布工具包已重建；完整生产版安装包没有在本次自动重建。共享源码中的版本与网络修复一致。
