# 发布版故障诊断、媒体浏览器与托盘（2026.10.19.2）

## 用户日志提供的事实

用户提供的 ZIP 仅有 publisher-events.jsonl，共1144条事件，最后一条时间为2026年10月19日08:54:41。三个已执行平台均经过登录预检并进入上传；没有小红书上传失败的证据，不能据此断言全部账号登录失效。

- 抖音：两份视频两轮封面确认失败；第三份由用户停止。旧实现要求全部匹配按钮总数为1，可能被隐藏或禁用的同名按钮阻塞。改为严格限定唯一可见、可用的确认按钮，仍要求检测到视频/画布并等待封面处理关闭，歧义不点击。
- 快手：四次等待上传就绪均约30分钟，编辑区和发布按钮已经出现，但缺少本次完成证据及视频元数据。不把可见发布按钮当成完成，不降低发布成功标准。
- YouTube：在视频语言下拉框直接点击时发生1秒超时。改为有界等待可操作状态、识别已打开菜单、防止反复点击开关，并等待设置回读。保留原草稿ID继续、两次尝试上限及未确认结果核验，不清账本、不自动重传草稿。
- Google Drive：日志含64次连接错误。另有 upload.youtube.com 网络挂起错误；它们不能由可选请求的401或浏览器解码修复来替代诊断。网络、VPN、电源等目标机条件仍需现场验证。

## 部署版媒体浏览器差异

开发机离线实测：旧部署锁定环境 Playwright1.56 / Chromium141.0.7390.37 对 H.264/AAC 的 canPlayType 为空，测试视频元数据未就绪；完整版 Playwright1.63 / Chromium153 可解码。同版本官方 Chrome for Testing141.0.7390.37 可解码同一份生成的1秒测试视频（readyState4、duration1）。这些是本机实验结果，尚未证明目标机每个失败均由这一原因引起。

发布包改为携带官方 Chrome for Testing141.0.7390.37，与现有发布版锁定的浏览器主版本一致，沿用原账号专用目录；不直接用系统155浏览器升级旧141账号目录。YouTube已选择正常Chrome/Edge手工登录的账号继续使用原浏览器与原专用目录。完整版使用相同的会话工厂与平台修复，默认浏览器维持当前运行环境。

## 为什么ZIP中没有截图和DOM

已确认导出函数只收集publisher-events*.jsonl，漏掉了failure_diagnostics中已归档的文件。用户ZIP中没有图片不能证明原采集全部失败；原日志有12次归档路径记录，但目标机文件不在本开发机，无法事后验证图片是否确实存在。

现在按钮名为“导出诊断包”，包含：

- 正常发布JSONL日志。
- failure_diagnostics/平台名/北京时间日期/中的失败任务结果、完整任务日志、最后截图和DOM，文件名带任务ID、时间戳及操作ID。
- diagnostic-manifest.json：文件数量、SHA-256清单、采集错误、缺失截图、日志声称归档但本机缺失的任务。
- 诊断包说明.txt。

截图和DOM分别尝试、分别记录错误。先截取最后页面，整页失败回退当前视口；DOM读取失败仍保留截图。截图失败不阻止DOM。浏览器未启动、提前关闭或连接已断开时明确记录原因；不能生成当时不存在的真实图片，也不使用其他任务图片代替。成功任务不创建失败平台/日期文件夹，继续使用正常日志。

只导出正常日志及指定失败文件类型，不导出账号配置、Google凭据、Cookie或浏览器目录。更新之前没有取得的历史证据无法补造。

## 部署版系统托盘

支持Windows通知区域图标（可能在“^”隐藏图标中）：

- 点击或双击打开主窗口；重复启动程序也激活原实例。
- 右键：打开主窗口、运行设置、停止监听和部署、退出。
- 点击主窗口右上角关闭时隐藏到托盘，任务不停止；首次给出说明。
- 停止操作保存STOPPED、取消等待中的任务并停止监听及部署，等待在途操作安全返回。
- 退出沿用安全关闭流程；运行中可选择保留下次自动恢复或停止后退出，取消则继续运行。图标在安全关闭完成后移除。
- 使用--autostart自动启动且托盘可用时不展开主窗口。首次正常双击启动仍显示界面。没有可用托盘时关闭窗口沿用原退出流程，避免留下不可管理的后台进程。

本功能只用于部署版窗口，不改变完整版的窗口关闭习惯。
